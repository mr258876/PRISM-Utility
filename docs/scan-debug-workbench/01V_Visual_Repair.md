# PRISM ScanDebug — 01V 视觉与交互收敛

核对日期：2026-09-26。目标：用户当前 `dev` 工作树。

## 0. 本轮是什么

这是布局与交互修正，不是阶段 04 延续，不授权 Page/ViewModel/会话/对话框/Canvas 所有权拆分。

本说明来自对公开 dev 源码、DESIGN.md、阶段 01 任务书与实施记录的静态审查。本次没有运行 Windows 程序，没有取得用户当前截图，也没有固定或验证远端 HEAD。下面源码位置必须在实施前用当前工作树复查；早期报告数字不是当前版本实测。

保留所有现有业务能力、命令语义、取消与互斥、输入草稿、持久化规则以及最近生命周期修复。允许重新编排旧区域内部内容；“保留旧功能”不等于“旧表单整块原样保留”。

本轮不新增测量算法、对焦曲线、冻结或基线功能；已有这些能力则保留。不升级依赖、不引入网页运行时、不修改硬件协议、不为截图发送硬件命令。

## 2. 优先级与明确实现要求

### V1：先归还主观察区的高度

- 普通采样状态下，配置名称、未保存提示、保存与配置菜单位于同一条紧凑配置栏；窄版允许受控换行，不强制在所有宽度分三层。
- 配置保存保持明确可达，但日常采样时不与“开始采样”同时争当最突出动作。页面主要强调操作随上下文设置，不能全页处处 Accent。
- 运行状态靠近运行控件。关键禁用原因、错误和待审查提示可见，普通说明不在多个区域重复。
- 预览视图选择和辅助工具尽量合并成一行；确实放不下时仅把辅助工具放入原生溢出菜单。停止采集、全部电机停止不进入溢出。
- 不靠减小所有字号、缩放整个页面、全局强制 MaxHeight 或裁剪内容获得空间。
- 正常状态和审查展开状态分别设计。详细校验/导入审查放在同 Page 的专门工作区/披露区，保留明显入口与返回，不让顶部变成第二张大表单。

### V2：让任务切换真的有选中状态

- 四任务采用单选导航语义。优先现有 WinUI SelectorBar；不足以容纳本地化标签时用同一选择源的 ComboBox。不得依赖四个普通 Button 的键盘焦点冒充选择。
- 当前任务必须始终可辨认；指针离开、焦点进入输入框、错误导航后仍正确。
- 不新建与现有选择状态竞争的业务 ViewModel。同步任务入口、配置入口、问题导航，避免递归。
- 标签切换只改变视图，不执行 Apply/Save/Start/Stop/Reload。
- 移动或折叠手动点动控件前，维持现有捕获释放与取消保护。

### V3：重排默认内容，而不是只换六个旧区域的名字

- 采样：首屏优先通道、行数及当前采样相关参数。输片参数按采样方式展开；完整采集计划/输出设置移入配置编辑，不丢弃、不静默忽略原有校验。
- 黑白场：优先当前通道、当前黑白参考值/手动编辑、主要自动校准动作与 ROI 摘要。全通道档案状态、复制清除、完整校验明细为次级披露；有阻塞或待确认结果时保留明确提示和入口。
- 对焦：优先手动/自动对焦动作、当前结果与 ROI 摘要；ROI 数字编辑、算法参数、映射说明可展开。
- 运动：优先轴/角色选择、当前状态、点动及停止；底层电机配置按轴披露。不伪造实际位置。
- 不复制有状态编辑器造成两份相互回写的草稿；移动现有编辑器或使用同一来源的只读摘要。
- 沿用旧名称与命令可以，但需要更新 FindName、延迟加载、错误导航、AutomationId 和相应测试。

### V4：保留 WinUI 风格，减少相同层级的大卡片

- 保留主题资源、原生控件模板、焦点、禁用和高对比度状态。
- 一个任务轨/检查轨外层容器即可，内部小分组优先标题与留白，而不是每层再套完整同色同描边卡片。
- 约 300 DIP 参数轨内，长标签和普通设置采用单列表单。只有短小且成对的值（如 ROI 起止）保留双列，并在更窄时切换单列。
- 不删除必要标签，不把 Placeholder 当标签，不把完整帮助文本全部塞到首屏。短摘要后提供可键盘访问的详情；关键风险不能只放鼠标 ToolTip。
- 本轮必要的页面局部设计规则同步更新 DESIGN.md；不得为了改一个页面重做全应用主题。

### V5：把“信号检查”改成读数区，不是文字说明栏

- 有可靠数据时，优先列出少量关键数值及其单位，然后列出当前通道、ROI 与采集来源。
- 来源、设备确认依据和参数比较的完整说明可展开，摘要保留未知、未应用、来源不匹配等重要状态。
- 使用已有结构化数据或增加纯只读 UI 投影；禁止解析面向用户的本地化长字符串提取数值。
- 同一时刻选择一个主要位置显示完整 RAW 统计。中版/窄版可以按布局迁移披露位置，但不可让信息变成不可访问。
- 主图从可用高度布局，不把增加纵向滚动当作默认解决方案。图像缩放/平移自己的滚动保留，与整个图表报告滚动区分。
- 无采样明确为空。不要为了好看加入看似实测的占位数值。

### V6：响应式以实际空间和任务连续性验收

- 记录页面根节点实际宽高、DPI/缩放、Shell 状态。不能把 1920 物理像素当作 1920 DIP。
- 900/1280 是旧初始值，不是不可变要求。根据实际参数最小宽度、图像最小可用宽度及检查区需要重新验证；不为了显示三栏强行压缩主图。
- 两栏是正式的一等布局，不能是三栏失败后的残缺版。对一般桌面窗口，调参和观察应尽量同时可用。
- 宽度和高度分别处理：宽而矮的窗口也需要收紧顶部、折叠低频内容。
- 保留现有一个主图控件树/数据所有者。不要为每个响应式状态复制 Canvas。
- 保留单一布局计算来源；需要增补高度约束时在现有布局路径中处理，不建竞争的布局引擎。

## 3. 视觉验收：先测量，再判断

下面是本次建议的产品验收目标，不是微软控件规范，也不是已有通过结果。以默认文字缩放、正常非模态/非审查展开状态衡量。辅助功能大字、异常详情展开应记录单独降级行为，不得以裁剪换取达标。

| 实际 ScanDebugRootGrid 尺寸 | 场景 | 建议可视主图高度下限 |
| --- | --- | --- |
| >=1280 × 720 DIP | 日常采样，宽布局 | 420 DIP |
| >=1000 × 600 DIP | 日常采样，两栏 | 320 DIP |
| >=720 × 560 DIP | Compact，明确打开预览 | 280 DIP |

- 衡量的是图像/图表可视视口，不是外围卡片高度，也不是 Canvas 的 DesiredSize。应扣除不可见裁剪/遮挡。
- 支持尺寸内发现不足，需修改布局或明确报告失败；不能把几十/一百多 DIP 的观察区直接写成视觉 PASS。
- 在实际用户窗口/DPI下额外验收一次；若尚未提供，先完整记录当前 Windows 测试环境，不猜测用户屏幕。
- 所有主要任务均拍默认首屏。除专门的长内容用例外，不先手工滚到“最好看”的位置。
- 任务选中态必须可辨；主动作可见；参数无水平裁剪；停止始终可达；鼠标之外键盘也能打开帮助和详情。

## 4. 最小截图与交互矩阵

实际捕获以下代表性状态即可，不要求无止境地穷举所有组合：

1. 中文、默认采样、无设备/无数据的诚实空态，两栏。
2. 中文、带已知来源的静态测试帧，宽版与两栏各一张。
3. 黑白场默认首屏与手动黑白值编辑。
4. 对焦默认首屏；确认主动作在 ROI 完整表单之前。
5. Compact 预览、返回参数、打开/关闭检查，确认选择与草稿不丢。
6. 英文一次代表性布局、浅色一次、高对比度一次；覆盖代表性 100%/150%/200% 缩放，并记录实际达成尺寸。

静态测试帧优先使用已有离线/QA入口。允许仅在现有 QA/测试宿主中注入明确标记的固定 fixture 来验收已存在的数据呈现，不允许它进入生产设备状态或假装实测。没有可用安全入口时以空态交付，并把带数据截图标记未验证，不扩大本轮去建设新模拟平台。

每张截图旁记录：HEAD、构建配置、主题/语言、窗口物理尺寸、XamlRoot.RasterizationScale、根内容区 ActualWidth/ActualHeight、视口实测宽高、布局模式、数据来源。截图必须来自真正的 WinUI 运行，HTML/设计图不可替代。

至少人工查看前后对照一次；UI Automation 找到按钮只能证明可达，不等于画面通过。

## 5. 测试、报告和停止条件

- 构建/回归继续保留现有命令、持久化、ROI坐标、手动点动、焦点与生命周期安全测试。
- 合理更新旧布局常数/旧控件排布的断言，不能为了满足陈旧断言把坏布局锁死；同时保留其安全与行为不变量并增加新行为检查。
- 分别报告：代码完成、构建、行为测试、WinUI实际运行、视觉验收、实机验证。不用 managed tests 数量替代视觉验收。
- 执行一次有界的修正：先基线截图/测量，完成 V1–V6，进行一轮对照和必要修正；剩余不达标项如实列出，不自行开始新的架构工程。
- 没有 Windows 环境时，可以完成安全的代码修改与可运行测试；原生视觉状态必须标为 NOT_RUN，不能声称已解决实际外观。
- 不自动开始阶段 04、QA生命周期工程或新图表功能；不擅自 reset/clean、提交或推送。

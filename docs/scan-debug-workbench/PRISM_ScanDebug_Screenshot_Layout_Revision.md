# ScanDebug：基于原生截图的布局修订稿

## 0. 本轮目标与执行边界

目标不是继续“美化卡片”，而是替换旧的纵向表单排列，得到保留原生 WinUI 3 风格的操作工作台。**保留业务契约，不等于保留旧 XAML 视觉树。**

默认本轮只实现：公共布局骨架 + 黑白场任务的完整首屏。使用相同实际页面尺寸，提交两栏和宽版各一张原生截图，并检查相关交互。其余任务沿用既有功能，不在这轮顺手重构。本文第 6 节给出的其他任务方向属于后续设计，不授权一次性全部实施。

禁止进入阶段 4、抽取新设备会话、替换预览渲染管线、升级依赖、引入 WebView2、改协议、修改算法、改变停止/取消语义、改变配置持久化与参数写入时机。不要把视觉修订变成新的 QA 框架工程。

先读取 AGENTS.md，核对当前 HEAD 和工作区修改。本文不声称截图二进制等于实施时的最新 HEAD；记录实际基线。

## 1. 观察依据与边界

本次观察的默认首屏截图来自：

`docs/scan-debug-workbench/implementation-notes/01V-evidence/after/ready-probe-release/`

已查看：`two-column-*` 与 `wide-*` 下 Sampling、BlackWhite、Focus、Motion 的 8 张 `default-empty.png`；另查看两栏 inspection、preview-flyout、ManualWhiteLevelTextBox-draft 三张操作截图。

尺寸来自同目录 `native-inprocess-measurements.json`，不是从聊天里缩小后的图片估算：

| 状态 | ScanDebugRootGrid（DIP） | 图像可见视口（DIP） | 图像高度/根布局高度 |
|---|---:|---:|---:|
| 两栏默认空态 | 977 × 604 | 645 × 230 | 约 38% |
| 宽版默认空态，检查区关闭 | 1305 × 809 | 950 × 435 | 约 54% |

截图是中文、深色、200% 栅格缩放、设备离线、无预览帧的 QA 构建状态。不能据此判断在线按钮配色、真实 RAW 图表、真实采集性能或设备动作。仓库 `01V-visual-repair.md` 已记录视觉判定为 REVISE；构建、截图捕获完整性与视觉通过不是一回事。

关键可见问题：黑白场默认首屏没有完整呈现白值及应用操作；运动任务的执行动作仍在首屏以下；对焦的数值说明在窄格中换行；显示选项存在嵌套浮层；检查区在两栏模式中替换了参数区。

## 2. 需要改的设计决定

### 2.1 从“堆卡片”改为“一个工作台，两块工作表面”

配置身份与运行控制不再各自成为一张大卡片。默认主要内容表面只保留：参数区、观察区。正常状态文字轻量化；错误、待审查候选与真正阻塞原因仍有明显入口和必要提示。

保留已实现的原生任务 SelectorBar，不回退为普通按钮。

不要用统一缩小字号、控件缩放、降低透明度、压缩点击目标来补救布局。不要为了看起来有强调色而解除离线禁用状态或使用假连接状态。

### 2.2 允许收窄本页面的 Shell 留白

核对以下现有位置：

- `PRISM Utility/Views/ShellPage.xaml` 的内容宿主。
- `PRISM Utility/Styles/Thickness.xaml` 的 `NavigationViewPageContentMargin`，当前读取值为 `56,24,56,0`。
- `PRISM Utility/Views/ScanDebugPage.xaml` 的页内边距，当前读取值为 `12,12,12,24`。

因此在这些层上，左右至少各有 68 DIP 边距，尚未计卡片内边距。

允许给 ScanDebug 设置独立内容边距策略，使 Shell 内容区到工作台左右有效留白各约 16–24 DIP。不是将全局资源一刀切成小值。必须检查从此页面离开、进入其他页面以及返回时的恢复。不要以负 Margin 抵消祖先边距，不要在子 Page 放一个同名资源就假定它能改变祖先已经解析的 StaticResource。

保留系统标题栏与现有应用导航，不自动强制收起用户打开的导航。仅提供/沿用已有导航折叠操作。

### 2.3 修改冲突的页面局部设计规则

允许更新 `DESIGN.md` 中 ScanDebug 的以下布局规定：任务切换占一整行、光标信息必须放在上方工具栏、正常状态必须以独立卡片呈现、配置操作一律全部常驻等。

更新后仍保留：参数状态真实、关键停止入口常驻、错误和候选可发现、命令与保存范围明确、原生主题和键盘可访问性。不要把被本轮替换的旧布局规则继续作为源码契约测试强制保留。

## 3. 公共布局：明确区域，而非自动堆叠

### 3.1 正常状态骨架

```text
配置身份与状态                                      保存  配置菜单  审查
采集模式 / 简短设备或任务状态               开始  停止采集  停止全部电机

采样 黑白场 对焦 运动       图像 线剖面         缩放 / 显示 / 检查
┌ 参数工作区 ──────────┐   ┌ 主观察区 ───────────────────────┐
│ 当前任务的完整动作组  │   │                                │
│                     │   │                                │
│ 低频详情按需展开    │   │                                │
└─────────────────────┘   └────────────────────────────────┘
简短状态 / 事件入口                    当前图像来源 / 有效光标读数
```

任务选择与预览工具在**同一个工作区头部行**左右对齐，不再前后占据两个整宽行。不同区域属于各自列：任务选择只支配参数区；图像/线剖面与显示工具只支配观察区。

窗口收窄或英文标签不适配时，根据选择器实际可用宽度切换为 ComboBox。不要用截图中的中文短标签证明所有语言都能放下。

### 3.2 顶部具体要求

配置行：标题、配置名、修改状态有清楚的间隔和主次，不拼成一条无分隔长句。配置名可省略，完整名称可读取。次要文件操作使用有标签的菜单；保存可保留一个紧凑入口。审查在有待处理项时显示实际状态，不制造计数。

运行行：使用 Grid 明确分配模式、状态与按钮的位置。不要继续将“带上置 Header 的 ComboBox”与无 Header 的按钮放进同一 WrapPanel，造成按钮与输入框基线错开。模式可采用行内标签或显式标签/输入网格。

常态下简短状态与按钮同排。错误、忙碌阶段、阻塞原因有必要时才扩展。不得裁掉真实错误，不得只保留无法通过键盘读到的 Tooltip。

停止采集与停止全部电机仍是不同动作，不改成统一取消命令。不将停止入口移入溢出菜单，不为了截图改变 CanExecute。

### 3.3 视口预算

以下为这次设计目标，不是微软标准，也不是现状通过结论：

- 实际根布局约 977 × 604 DIP、正常中文默认文本缩放、检查区关闭时，完整图像可见视口高度至少 380 DIP。
- 实际根布局约 1305 × 809 DIP、相同状态时，至少 580 DIP。
- 目标从同一份自然布局产生，不给两个尺寸各硬编码 Canvas 高度。
- 在上述常态中，将根布局到图像视口之外的垂直开销控制在约 220 DIP 以内，是推荐的空间预算。

实现参考：身份行约 40–44 DIP、运行行约 40–48 DIP、工作区局部头约 40–44 DIP、简短页脚约 24–28 DIP，其余为合理间距。它们是设计预算，不是给包含长文本的容器强设 Height。正常使用 Auto / 星号布局，保留控件原生最小尺寸。

测试时必须通过调整窗口重新达到约定的**实际 Page / Root 尺寸**。修改 Shell 留白后根布局可能变大，不准只用更大的根布局宣称在原尺寸下达标。记录 Page、Root、视口三个坐标系和实际大小。

扩大系统文本、展开错误/候选详情、极矮窗口另行验证可达性；允许视口目标让步，不允许裁剪、隐藏停止操作或锁死滚动。

### 3.4 预览头与空态

只保留当前视图、常用缩放/适应窗口、显示、检查等入口。当前无帧时不要用两行无意义的光标占位抬高头部。有有效读数时，用同一行或已有底部状态区表达。

“显示”直接打开一层包含 Gamma、白点、瀑布等现有显示控制的浮层。不要继续“更多工具 → 预览配置 → 第二层设置浮层”。其他低频工具可以分类收纳，但关键停止不进菜单。复用现有缩放和显示逻辑，不新写一套变换。

空态显示一条清楚说明。可提供“查看设备状态”或现有配置入口，但只能调用现有导航/状态界面，不自动连接、发送硬件命令或添加无关导入功能。

若在空态容器内加按钮，注意当前 `PreviewEmptyStateGrid` 使用 `IsHitTestVisible=False`。不能只塞入不可点击的按钮；应处理空态专用交互层，并确保有帧后整个空态层折叠，不截获缩放、拖动与 ROI 指针事件。

## 4. 黑白场：一个完整动作组，不能把白值与应用藏到下方

参数区初始宽度建议约 320 DIP；与预览一起按实际可用宽度验证，不能强行三栏。

默认首屏内容顺序：

```text
通道 [当前逻辑通道]       LED 映射摘要

手动黑白参考值 · RAW ADU
黑参考值          白参考值
[输入框]          [输入框]
[应用到通道]      [撤销本次编辑]
必要时出现一条准确的禁用或校验原因

自动校准
[黑场/偏移] [白场/增益] [完整校准]

当前 ROI 摘要                         编辑
▸ 档案、校验与高级参数
```

按钮最终文字必须与当前命令的真实效果一致；上面是布局表达，不授权改变校准算法或把手动参考值等同于 ADC 硬件值。

要求：

1. 黑/白参考值适合两个短数值并排；这是成对输入特例，不是将所有表单恢复为窄栏双列。宽度或文字缩放不足时，两行排列也必须与操作按钮一起得到合理空间。
2. 在约定两栏尺寸默认首屏中，两个完整输入框及应用/撤销按钮必须可见。不能用 UIA `offscreen=false` 将仅露出 2 DIP 的控件算作通过。
3. 控件下边缘和焦点边框不得被遮挡。必要时增加真实滚动，但默认应优先容纳这个主要动作组，而非描述文本。
4. 通道与物理 LED 映射摘要只展示一次。缺少通道档案时提示一次，保留现有禁用条件和明确的配置入口；不自动创建档案来消除提示。
5. 继续使用现有输入、校验、应用、撤销命令。不得因视觉调整变成输入即保存、失焦即应用或编辑即发送设备参数。
6. 未设置保持未设置，不将空值转零。不截断非法输入；校验路径可读。
7. 切换任务/通道、展开详情不应偷偷应用草稿。保持输入归属与既有未保存修改保护。
8. 三个自动校准动作必须仍可访问；不得为了瘦身删除、合并效果或更改取消行为。
9. 导入候选、校准候选、阻塞校验和待审查状态有提示及正确入口。不能为满足高度目标隐藏必须处理的状态。

## 5. 原生视觉规则

主要参数和观察区使用现有主题资源，不给每个小组再套一张同等重量的卡片。文字标题、分组间距和控件对齐承担层级。

使用原生控件样式和真实选中/禁用状态。不要增加仿网页胶囊、发光描边、渐变、装饰性仪表读数，也不要统一把字体改小。

数值字段、单位、说明对齐。普通短说明单行或按完整区域换行；风险/范围提示不省略关键数值。中文、英文和高对比度保留可读性。

重复的“未连接/请连接/等待设备”不必在所有区域完整重复。保留一个主状态和每个任务必要的局部上下文，详细设备标识可在既有详情中查看。不要把仍有意义的错误与安全提示当作重复文本删掉。

## 6. 后续任务方向（不在默认首轮实施范围）

### 对焦

将点动输入与按钮组成一行，限制/风险说明放在下一行横跨整组，避免摘要受输入格宽度限制而将数值和单位拆开。不能删掉边界保护说明来改善观感。

保留现有快速、运行、精细、停止等命令；先核对差异，再用分组和准确命名说明，不凭名称推断可合并。保持原有按下/释放/取消/捕获丢失语义，不重写为新的运动方式。

### 运动

用轴/角色选择组织当前动作组，而不是三份长表单依次占用首屏。角色与编号来自现有映射，不能硬编码。方向、距离与单位、速度与单位、有效移动摘要、移动与停止在一个紧凑组内。

隐藏其他轴的编辑区不代表删除其他轴的停止能力；保留全局停止和既有每轴停止入口。选择轴只改变视图，不能重置电机参数、写档案或发命令。

### 检查区

两栏中优先保持参数区和图像坐标稳定。短读数可紧凑显示，完整检查详情采用临时覆盖式侧栏或既有可恢复详情，避免打开检查就用它替换参数区、把图像整体搬到左边。

采用覆盖式侧栏时允许临时遮住部分图像，但不改变图像缩放/ROI 坐标、不将被覆盖区仍计为完全可见视口。关闭后恢复焦点；打开时不夺走活动点动的所有权。保持旧数据来源、统计定义与安全语义。

## 7. 本轮允许修改的范围

- `ScanDebugPage.xaml`：公共行列结构、任务头、黑白场排列、样式资源、空态与菜单。
- `ScanDebugPage.xaml.cs`：必要的可见性/布局/焦点和导航编排；保留页面会话、epoch、对话框、资源释放等已有修复。
- 本地化资源：准确短标签、分组说明与可访问名称。
- Shell 内容宿主：只允许 ScanDebug 专用留白策略及恢复，其他页面视觉保持。
- `DESIGN.md`：同步被本任务替换的页面局部约束。
- 必要的局部只读呈现状态、布局计算和已有测试更新；不引入新的硬件 owner 或整套 ViewModel。

不要为通过测试恢复本轮明确废弃的旧行列结构。不要大面积改无关类或将单个页面重排变成组件拆分项目。

## 8. 验收与明确停止点

### 本轮必须交付

1. 同一构建的两张原生黑白场默认首屏：根布局约 977 × 604 与 1305 × 809 DIP，检查区关闭。两张都展示完整配对输入和动作区。
2. 对应 Page/Root/可见视口几何记录；按本文目标报告实际值。截图保持原生比例，不能用拼接/生成图充当结果。
3. 黑/白输入、应用/撤销、切换任务保持草稿、原有校验入口、显示菜单、预览缩放/ROI、Shell 导航恢复的相关验证结果。涉及硬件动作的项目不得在未获授权/未接设备时假称验证。
4. 构建与相关测试结果，以及没有进行的原生、语言、主题、实机检查。

首屏检查采用**整个动作组完整可见**，而不只是控件存在、有 AutomationId 或部分露出。要检查实际裁切、文字换行、焦点边框和按钮可达性。

当前任务只做有限的“实现—截图—修正”循环，建议最多两轮。仍未达目标就提交具体未达项与剩余原因；不要用无限补充报告替代交付，也不要把 REVISE 改写成 PASS。

若无法运行 WinUI，继续完成可执行的代码与测试，明确 `NATIVE_VISUAL_NOT_RUN`，不能用源码断言或 HTML 预览声称原生布局达标。不要为本次视觉任务重新搭建复杂的捕获平台。

**通过这两张目标截图和核心交互后，再授权其他任务面的同风格重排。不要同时扩展阶段 2/3/4。**

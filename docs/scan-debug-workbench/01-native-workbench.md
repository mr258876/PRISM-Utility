# 阶段 01：原生 WinUI 3 工作台布局

> 先读 [README.md](README.md)。本阶段是默认交付范围。
> 状态：待实施。目标：**界面重组，功能和命令语义不变**。

## 1. 范围与禁止事项

将现有 ScanDebug 改成固定运行栏、任务参数、主要预览、可折叠检查区的原生工作台。第一版必须能完整承接旧功能；不要求新增测量图表或手动黑白参考值。

允许修改页面 XAML、布局与控件交互 code-behind、必要的纯 UI 投影、页面资源、本地化和相应测试。允许扩展现有布局计算，不提取 Page／ViewModel 的会话、预览、对话框或生命周期所有权。

不得修改 Core 设备控制、扫描协议、自动校准／对焦算法、采样模式、保存格式和硬件动作顺序。不得把现有数值输入一次性全部换成 `NumberBox`。不把“停止采集”悄悄改成全任务取消。

## 2. 开始前：完成功能迁移清单

### P1-01：既有能力盘点

核对 XAML、code-behind 动态控件／绑定、ViewModel 命令、partial 文件与相关测试。不能只搜索 XAML 后断言某个功能不存在。

报告中至少列出以下类别的旧入口、新入口、命令与关键状态：

| 原能力类别 | 新界面默认位置 |
| --- | --- |
| 当前配置、New／Open／Validate／Save、未保存提示 | 顶部配置条与配置操作菜单 |
| 暂存导入、校验、应用／放弃、丢弃修改确认 | 配置编辑／导入审查区域，关键待处理状态在顶部可见 |
| 基本信息、采集计划与输出设置 | 配置编辑工作区；不塞进普通参数 Flyout |
| 通道档案、状态、复制／切换与校准候选结果 | 黑白场／通道区域及结果审查 |
| 采集方式、行数、通道、启动与停止 | 固定运行栏＋采样参数 |
| 原始参数、时钟、照明、预热等现有操作 | 采样参数／工程参数，保留应用范围 |
| 黑白场、ADC、ROI、列采样参考值保存 | 黑白场参数及原有工具 |
| 自动对焦、手动点动、按住移动、映射测试 | 对焦任务区域 |
| 输片与其他运动、限位／状态、全部停止 | 运动任务区域＋常驻全电机停止 |
| 预览开关、图像／瀑布、Gamma、白点显示、缩放、ROI、像素值 | 中央预览及工具栏 |
| 加载数据、DNG 等已有导出 | 预览工具或明确的文件菜单 |
| 设备设置、工程工具、错误定位 | 高级入口与更新后的问题导航 |

清单要以当前源码为准；上述分组不代表每项都由一个独立按钮实现。任何能力移入菜单后仍必须可发现、可访问，错误定位可到达。

## 3. 页面骨架

### P1-02：固定区域与独立滚动

根布局使用约四个职责行：配置条 `Auto`、运行栏／状态 `Auto`、工作区 `*`、事件摘要 `Auto`。不允许整页外层 ScrollViewer 将运行按钮一起卷走。

工作区宽版包含参数、预览、检查三列。参数和检查区独立滚动；中间继承剩余宽高。大型配置编辑使用同一 Page 内的专用编辑状态／区域，不另建拥有相同 ViewModel 会话的第二个 Page。

顶部配置条：显示当前文件／配置名与原有保存状态，保留显式保存按钮；其他文件操作进入菜单。导入审查尚未处理时必须有可见入口；导入成功不能绕过原有 staged review 直接覆盖当前配置。

### P1-03：固定运行栏

显示现有任务状态、阶段和采集进度；保留当前采集模式选择。绑定现有 `StartScanCommand`、`StopScanCommand`、`StopAllMotorsCommand` 或工作基线等价命令。

- 不改变命令职责、取消令牌、互斥和 `CanExecute`。
- “停止采集”“全部电机停止”是两个入口；自动对焦等已有取消入口也不能丢失。
- 停止按钮位于不会自动溢出的独立容器，不放进“更多”菜单。
- 不给整条运行栏绑定一个会在运行时变为 false 的父级 `IsEnabled`。
- 宽度不足时运行栏允许两行，仍无需滚动即可找到停止入口。
- 全电机停止不得新增确认弹窗延迟命令；既有硬件访问条件和错误反馈保持。
- 进度无可靠总量时显示不确定进度，不伪造百分比。
- 长状态文字可换行／截断并提供详情，不能将按钮挤出视口。

### P1-04：任务参数与配置编辑

常用任务为采样、黑白场、对焦、运动。可使用一个主选择器控制局部可见性；不得嵌套第二套完整 Shell NavigationView。

基本信息、采集计划、通道档案编辑保留明确的“配置编辑”入口。设备全局设置和底层工程工具保留高级入口。未提交输入与当前通道在视图切换后保持；不要在 `SelectionChanged` 中顺带 Apply、Save、Stop 或 Reload。

四个任务页是信息架构建议，不要求把现有全部绑定改名。可以沿用旧区块名称和命令，以降低源码契约迁移成本。

### P1-05：预览区完整迁移

迁移原有 Win2D 预览、坐标轴、缩放、平移、ROI 编辑、列采样、图像／瀑布切换、显示处理、加载与导出入口。

复用同一个预览控件树／数据所有者适配宽窄布局；不因切换任务或宽度复制 Canvas 实例和订阅。控制视觉布局不要改变原始采样坐标含义，不将有效像素坐标与屏幕 DIP 混用。

第一阶段不添加无真实实现的线剖面／对焦曲线标签，不提供假冻结按钮，不显示合成测量值。已有图表则保留。

### P1-06：检查区与事件摘要

检查区优先聚合现有 ROI、列采样和来源说明。未获得可靠数据时显示“暂无数据”，不要推导“设备已确认”或伪造采集版本号。

检查区收起后仍有“信号检查”入口；现有 ROI 编辑控件的功能可达，且不创建两份互相回写的编辑状态。

事件区仅显示已有状态／日志入口或有限摘要。本阶段不新建全局日志后端，也不复制完整日志页面。

## 4. 自适应与原生风格

### P1-07：布局状态

按 **ScanDebug 实际内容区宽度（DIP）** 选择布局，而不是物理屏幕分辨率。优先扩展 `ScanWorkbenchPreviewLayout` 等现有实现，避免再造并行计算源。

以下为初始设计值，不是硬编码协议；根据中英文和现有 Shell 调整后写入报告：

| 状态 | 建议内容区宽度 | 行为 |
| --- | --- | --- |
| Wide | ≥ 1280 DIP | 三栏；左约 300、右约 260，中间优先；列宽可合理调整 |
| Medium | 900～1279 DIP | 参数＋预览；检查区默认收起，按需打开 |
| Compact | < 900 DIP | 参数／预览切换；检查内容复用同一所有者；运行栏保留 |

不能因固定列宽而让中间预览变成几十像素。建议在预览宽度接近 480 DIP 前收起检查栏；窄版至少测试 720 DIP 内容区。若当前应用最小窗口已不允许该尺寸，应记录实际边界，不擅改 Shell 限制。

低高度窗口须检查顶部换行、错误提示与预览占用。大型导入审查不能无限撑高顶部把工作区挤成零。无需隐藏错误，可使用摘要＋可滚动详情。

分栏拖动要 clamp 到安全范围；切换布局时保持可恢复比例，不能以负宽度或一次布局测量值写死后续状态。

### P1-08：WinUI 与可访问性

- 沿用现有 ThemeResource、默认按钮模板、原生字号层级和图标。
- 常用间距可统一为 8／12／16／24 DIP；这只是页面尺度，不重做应用设计系统。
- `CommandBar` 只容纳允许溢出的辅助操作。[S7]
- `SelectorBar` 空间不足时切换 `ComboBox`，沿用已有选择同步机制，避免事件递归。[S6]
- 新增文字写入现有中文／英文资源；关键参数带单位，图标按钮有 ToolTip 和 Automation 名称。
- 输入采用 Header／Label，不仅依赖 Placeholder；错误不只变红。
- 沿视觉顺序调整键盘导航；隐藏元素不能截获焦点。焦点在被折叠区域时转到替代入口。
- 所有相关弹窗继续绑定正确 `XamlRoot`；不要把本地事件处理变成无归属全局弹窗服务。
- 不把新的 Enter／Esc 全局快捷键绑定为运动、开始扫描或全局停止，以免影响输入和对话框语义。

## 5. 代码迁移风险

### P1-09：定位与绑定

逐项检查：`x:Name` 引用、`x:Uid`、AutomationId、分区索引、`FindName`／延迟加载、code-behind 动态绑定、校验问题导航、自动滚动、焦点定位、预览重排事件。

以当前实际代码为准，重点追踪 `CalibrationSectionRequested`、ROI issue navigation、配置校验问题到输入框的路径。修改导航映射时增加测试，不能只在截图里证明按钮移动。

### P1-10：生命周期保持

不更改 Page 的导航缓存策略，不改变 Loaded／Unloaded、Attach／Deactivate／Cleanup、取消、对话框 completion 和 CanvasBitmap 的资源所有者。[S3][S10]

新加的布局状态切换不能触发完整页面激活／释放；不能因某个子面板 `Unloaded` 就停用整个 ViewModel。确需新增事件时必须对称订阅／解绑，并验证多次加载不会重复订阅。

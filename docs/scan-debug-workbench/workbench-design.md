# ScanDebug 工作台设计

本文说明胶片配置与校准工作台的界面职责、数据来源和交互约束，供维护页面、ViewModel 与测试时参考。产品整体规则见 [DESIGN](../../DESIGN.md)，实现边界见[架构文档](../architecture/README.md)，未完成工作和规范差异见[统一待办](../TODO.md)。这里的设计原则不表示所有相关功能已经通过当前版本验收。

## 页面职责

工作台支持离线编辑胶片配置，以及连接扫描仪后的采样、校准、对焦和运动操作。文件配置、通道校准库、编辑草稿和设备状态分别管理，界面应让用户清楚当前操作影响哪个对象。

| 区域 | 主要职责 |
| --- | --- |
| 页面标题与配置身份 | 页面名称保持清晰的最高层级；配置文件名、修改状态和保存状态独立呈现。 |
| 配置操作 | 新建、打开、保存、编辑草稿和配置检查；暂存导入经过明确审阅后才替换当前配置。 |
| 设备与运行操作栏 | 呈现连接、当前任务、阻塞原因及下一步；开始、停止采集和停止全部电机保持可达。 |
| 四任务参数区 | 采样、黑白场、对焦、运动各自组织常用参数与次要设置。 |
| 观察区 | 显示图像、RAW 信号、冻结或基线状态，以及对应样本的来源。 |
| 问题与候选审阅 | 展示可定位的问题或待接受的校准候选，保留明确的返回路径。 |
| 配置属性与工程工具 | 配置属性管理基本信息与设备设置；工程工具容纳设备测试和诊断，并说明作用范围。 |

辅助面板与普通任务使用同一份输入和命令状态。入口位置调整不应创建第二份配置或绕过原有命令条件。图像导出、显示设置、完整配置保存和通道档案保存使用不同名称，避免同一个“保存”指代不同动作。

## 状态与数据来源

| 显示内容 | 数据语义 |
| --- | --- |
| 当前文件名 | 实际打开或成功保存的文件身份；未应用的导入和取消的文件选择不改名。 |
| 修改、保存与检查状态 | 修改表示相对编辑基线的变化；完整文件保存、编辑草稿保存和配置有效性分别显示。 |
| 通道校准状态 | 来自相应通道档案、当前输入及校验结果；“已保存档案”不等于完整配置已经保存。 |
| 设备映射 | 来自设备设置；与胶片选择的通道角色区分，缺失映射不能伪装为可运行。 |
| 设备确认值 | 只有已知读回或确认才能这样标注；未知、未读取、未连接和最后一次值分别表达。 |
| 图像和 RAW 来源 | 随采集样本或观察快照保存的来源；后续修改的编辑参数不能冒充旧样本的采集参数。 |
| 运行状态 | 来自结构化会话和操作状态；不通过解析本地化提示字符串决定严重性或命令可用性。 |

运行栏优先显示未解决的操作失败、正在执行或停止的任务、阻塞下一步的条件和就绪状态。活动任务与连接异常可以同时存在，不能用“未连接”掩盖尚待取消的本地工作。“没有正在采集”通常是停止按钮的禁用原因，不必与所有其他禁用原因并列为主状态。

真正的阻塞原因应在对应输入或运行区域可见，不能只放在工具提示里。普通帮助解释原因和选择方法；状态描述当前情况；错误说明问题及处理入口。配置问题和通道问题保留各自范围。

页头将参数检查、所选通道黑白参考值覆盖和保存状态分别呈现。“参数检查通过”只说明配置结构与输入值满足校验，不代表参考值齐全、实测校准质量或设备就绪。参考值覆盖要求当前配置中的白值大于黑值；缺少参考值仍沿用原有完整配置保存规则。通道行的“通道参数已配置”只说明通道参数存在，不能代替参考值覆盖摘要。四步入口使用“建议”措辞，避免将推荐步骤误读为完成进度。

配置文件使用标准菜单组织新建、打开、完整保存、编辑草稿和配置属性；页头保留常用保存与明确的“保存并用于扫描”操作。运行栏按各组控件和文案的自然宽度排布：足够宽时共用一行，否则将设备状态与辅助操作整组移到下一行，行间保持 8 个有效像素；离线也保留状态说明。无图像的离线预览可直接打开连接详情；打开详情本身不连接设备。电机和对焦的离线显示不再用空闲占位值冒充实时设备状态，未结束的任务和未处理的错误仍保持可见。

底栏用于图像尺寸、通道、采集来源、光标原始值和冻结状态等观察上下文，不重复播报连接状态。无图像时可以收起。移动或精简状态文本时，原有失败和结果仍需有可见入口；未解决的重要错误不能被低优先级成功消息覆盖。

## 输入、文件与设备边界

- 页面投影、布局重排、任务切换和只读摘要更新不自动应用参数、保存文件、创建通道档案或执行设备命令。
- 未应用的数字、ROI 和手动参考值属于编辑输入。查看问题、定位字段、打开辅助面板和返回任务应保留这些输入；撤销只恢复相应编辑器拥有的基线，不覆盖其他对象的更新。
- 观察范围、ADC 校准范围和对焦范围分别管理。将观察范围填入算法输入是显式操作，实际提交仍使用对应的应用命令。
- 自动校准候选的接受、接受并保存档案、恢复和取消保持独立语义；候选审阅不能隐式导出完整配置。
- `.prismdraft` 用于恢复编辑状态，可以包含尚未完成的输入；完整配置 JSON 仍须满足其结构和数值约束。编辑草稿不能直接作为扫描配置使用。
- “保存并用于扫描”依赖真实保存成功及有效的页面激活状态。保存取消或失败不导航，后续未保存编辑不改变已保存快照。
- 显示冻结不停止采集。冻结和基线使用独立的显示副本及其来源，不能从实时缓冲读取数值并显示成旧快照内容。RAW 统计不从经过显示变换的像素反推。
- 专用白光和 RGB 合成白光保留各自来源和配置语义；未提供的设备身份或读回信息保持未知，不能生成占位值冒充实测。
- 设备写入仍由相应服务与命令负责。页面卸载、重入和异步操作收尾遵守现有 owner、epoch 与取消边界，旧操作不能更新新页面。

停止、取消和点动释放不只是视觉状态。布局变化必须保留停止入口、指针松开与捕获丢失处理，以及既有运动限位和距离约束。离线时仍可用的停止动作可能用于取消本地工作，不能仅为外观统一而禁用。

## 四任务的内容组织

| 任务 | 常用内容 | 必须区分的概念 |
| --- | --- | --- |
| 采样 | 当前模式相关的通道、行数、预览和必要采集参数；传送策略、输出及完整计划放在次级分组。 | 隐藏不适用的字段不清除输入；采集照明配置与会话照明测试分开。 |
| 黑白场 | 当前通道、手动参考值、ADC 参数、ROI、校验摘要与候选审阅。 | 参考值应用、设备参数应用、候选接受、通道档案保存和完整配置保存分别呈现。 |
| 对焦 | 自动对焦、手动点动、对焦范围及次级搜索参数。 | 预览选区、对焦编辑范围和算法实际评价范围必须可辨，不能用黑白场摘要代替对焦来源。 |
| 运动 | 轴身份、方向、距离、速度、估算和移动/停止。 | 有可靠映射时显示机械角色；没有映射时保留原始编号及未知状态，不猜测物理正负方向。 |

同任务中的次要参数可折叠，普通操作避免多层嵌套菜单。命令使用按钮或菜单项，切换视图使用有选中状态的控件，不能为了视觉一致把所有入口都改成折叠面板。

速度与距离使用真实量纲；显示层的方向名称不改变底层协议值。会话照明、底层采集调试等工程操作在工程区域中保留必要的风险和作用域说明，普通任务仍保留日常采集需要的参数。

## 视觉层级与布局

以下是 100% 文字缩放下的角色基准，单位为 XAML 有效像素。使用 WinUI 主题字体、字体回退和动态文字缩放，不固定最终文本高度。

| 语义角色 | 基准 |
| --- | --- |
| 页面标题 | 28，Semibold；页面仅一处。 |
| 任务面板标题 | 16，Semibold；每面板至多一处。 |
| 分组或折叠标题 | 14，Semibold。 |
| 字段、按钮与正文 | 14；按钮保留原生控件样式。 |
| 时间、来源等辅助信息 | 12，次级色。 |
| 阻塞、风险与输入错误 | 不小于正文角色，允许换行。 |

同级折叠面板统一标题角色、内边距、箭头位置和宽度；展开时外框宽度不跳变。参数区和预览各保留清晰的主表面，内部使用小标题、分隔和留白，不为每段说明再叠一张卡片。间距优先采用组内 4/8、组间 12/16、区域间 24 的共享值。

字段标签位于输入上方。成对字段共享标签行与输入行，标签换行不应造成输入框错位；点动按钮与输入对齐。保留原生焦点、禁用、悬停、高对比度及点击区域。不能通过全局缩字号、负边距、固定文本高度或整体缩放掩盖裁切。

窗口变窄或文字放大时，操作区可以换行或使用紧凑任务选择器，但连接、反馈和停止入口仍须可达。长错误可使用完整详情或工具提示补充，主区域仍保留足以识别错误的信息。

空预览应说明当前可以做什么：离线时可编辑配置；设备就绪时指向首次采样；已有数据但没有预览时说明真实原因。冻结或旧帧不能显示成“无图像”。同一状态保留一个主要引导，避免顶部、画布和底栏重复相同提示。

空预览的参数区比例、最小宽度及辅助面板是否保留预览，尚有产品规范与实现差异，见[统一待办 X06](../TODO.md#兼容性与设计差异)。本文不把某一历史数值设为新的固定要求。问题列表的停靠与覆盖应服从当前可用内容尺寸，并保持导航、流程引导和停止操作可见。

## 导航与返回

首次进入任务应能找到常用参数；问题定位使用实际可见滚动容器。任务、配置属性、工程工具和候选审阅之间都有明确返回入口，切换本身不提交输入，也不产生设备动作。

不同任务不能共用错误的滚动偏移，普通状态刷新也不应无故改变阅读位置。哪些路由记忆滚动、哪些返回时复位仍需统一，见[统一待办 X07](../TODO.md#兼容性与设计差异)；历史的保留策略与当前黑白场复位行为不能同时当成既定规则。

移动控件时同步维护本地化、辅助功能名称、键盘焦点、错误定位和自动化查找。源码测试应保护输入和命令语义，不要求已经替换的容器结构永久存在。

## 验收原则

| 层级 | 需要证明的内容 |
| --- | --- |
| 托管与行为回归 | 输入保护、保存取消/失败、快照身份、旧异步结果拒绝、ROI 所有权、冻结副本与命令独立性。 |
| WinUI 原生交互 | 四任务与辅助面板切换、问题定位与返回、文件选择、点动释放、键盘焦点、关键操作可达性。 |
| 布局与可访问性 | 中英文、浅深色、高对比度、100%/150%/200% 显示缩放、较大文字、紧凑和可达到的宽窗口。 |
| 扫描仪验证 | 真实采集与来源、参数应用和读回、运动停止、断连取消、照明恢复及白光来源。 |

常规几何回归参考为根内容区 977×604 DIP、预览 645×396 DIP；宽版参考为根内容区 1305×809 DIP、预览 950×601 DIP。这些数值只用于可比的普通状态，不代表当前版本已经实测通过。较小窗口、文字放大和长错误状态另查内容与操作的可达性，不能通过扩大窗口、缩小字体或固定高度裁切来满足参考值。

记录实际内容区 DIP、物理像素和文字缩放，不能把请求但未达到的窗口尺寸计为通过。原生控件渲染能检查布局，但不等于桌面系统材质；隔离或合成数据显示只能证明相应显示行为，不能替代实机结论。源码断言和测试数量也不能单独证明视觉与交互质量。

可复现的测试数据与自动化随代码维护；开发截图、临时日志和本机运行产物不作为仓库必备文件。当前失败、未验证范围和后续工作统一记录在[待办](../TODO.md)，日期变更记录只描述当时的修改及验证边界。

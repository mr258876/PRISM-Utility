# 阶段 02：状态可信度与黑白参考值手动编辑

> 先读 [README.md](README.md) 和阶段 01 实施报告。
> 状态：待实施。建议按 02A 状态、02B 手动参考值两个独立变更集完成。
> 本阶段不包含新的 ADC 校准算法、自动对焦算法或图表。

## 1. 前置条件与实施范围

确认阶段 01 的既有功能迁移没有改变命令语义。复查当前工作区、通道档案、运行互斥、候选校准与设备会话实现，优先使用已有模型。

可以增加只负责表达状态的不可变数据、小范围输入校验／workspace patch、相应命令和测试。不得平行创建第二套设备状态机、JSON 文件格式、档案库或会话服务；不得重写全部 ViewModel。持久化 schema 原则上保持不变。

当前有列采样保存黑白参考值、通道档案和参数应用入口，先追踪实际调用链，不假设手动参考值与 ADC offset/gain 是同一种设置。[S2][S11]

## 2. 02A：让状态有明确来源

### P2-01：动作与数据范围表

实施报告必须列出当前行为和目标 UI 文案，至少区分：

| 用户动作 | 目标／副作用 | 不得暗示 |
| --- | --- | --- |
| 编辑输入框 | 本地编辑状态／工作区草稿，按既有契约 | 已经写入设备 |
| 应用通道参数 | 原有参数命令的明确设备作用域 | 已修改所有通道或已保存 JSON |
| 更新设备时钟 | 原有全局时钟流程及关联重验证 | 只影响当前通道 |
| 应用照明 | 原有照明命令和物理通道映射 | 协议 level 一定等于线性亮度 |
| 应用手动黑白参考值 | 当前胶片工作区的目标通道草稿 | 已修改设备 ADC、已保存 JSON |
| 保存配置文件 | 原有文件保存流程 | 设备参数与文件一定相同 |
| 已有本地通道库保存 | 仅当保留的原入口本就承担持久化时执行 | 等同于配置文件保存或新手动编辑的自动副作用 |
| 接受校准候选结果 | 按实际现有流程应用／接受，保留恢复和保存的不同动作 | 仅调整草稿、或保证质量合格 |
| 开始采集 | 使用原有 workflow 的实际有效参数 | 一定使用屏幕上所有未应用输入 |

保留既有参数提交策略。只有本阶段新增加的手动黑白参考值明确规定为“编辑不提交、显式应用到通道草稿”；不得顺手改动所有现有输入的行为。

### P2-02：设备状态按证据显示

复用已有会话、时钟、通道重验证、参数应用结果等状态，增加必要的 UI 投影：

- 草稿与已知设备参数是否不同。
- 参数提交进行中、命令成功、读回确认、失败、需要重新读取。
- 相关设备会话身份／代际与参数作用范围。
- 当前操作为何禁用。

只得到命令成功时使用“已提交／命令已确认”等准确表达；只有读回或现有契约确实保证时才写“设备读回值”。没有读回接口时不新增轮询来伪装验证。

断连、切换设备或时钟使既有校准失效时，复用当前失效规则更新显示。不能保持绿色“已生效”；旧数据可继续查看，但必须标识为历史采集。

设备控制链路、图像接收状态、外设可达性可以分别呈现，但缺少来源的字段必须未知，不能从单个 `IsConnected` 推导全部状态。[S12]

### P2-03：采集来源上下文

优先扩展／组合现有 capture／workflow result／parameter snapshot。在真实采集请求定型和提交的边界捕获来源；不能在完成回调里从当前 UI 重建。

最少需要表达的语义（不是强制新建同名字段）：

| 信息 | 要求 |
| --- | --- |
| 数据标识 | 能唯一关联当前结果或流式结果版本；多通道可区分 pass |
| 会话 | 采集时的设备／会话代际；未知可为空并注明 |
| 通道 | 采集时逻辑角色、物理 LED 映射及映射版本／快照 |
| 参数 | 实际使用的参数快照；区分请求值、已确认值和未知 |
| 采样方式 | 单次／连续／输片、有效行数、相关几何条件 |
| 时间 | 真实采集／完成时间；文件加载时间不能冒充采集时间 |
| 配置来源 | 有效的配置／校准标识；未记录时明确未知 |
| 数据处理阶段 | 设备原始、几何处理后的通道或合成图；不可混称 RAW |

历史或外部加载数据缺元数据时显示“原采集参数未知”。本阶段不为此强制修改 DNG／原始导出格式；不能把当前设备参数贴到历史数据上。流式更新记录已完成行数／pass 版本，不能读取尚未完成的行。

### P2-04：状态比较必须表达正确的差异

分别判断：

1. 编辑草稿是否不同于设备已知值。
2. 当前显示数据是否来自设备当前已知配置。
3. 文件是否有未保存修改。

它们不是一个笼统 `IsDirty`。

例如草稿由 250 改成 300，但设备仍是 250，图像也来自 250：显示“草稿尚未应用；当前图像仍对应上次采集”，不要错误宣称图像已经不对应设备。

参数应用完成但尚未复采：显示“设备参数已变更，当前仍为旧采集”。显示 Gamma 变化只影响显示处理状态，不改变采集来源，不要求为了改变 Gamma 重新扫描。

可以用内容比较或版本标识，但版本递增不是设备成功证据，不能仅凭编辑次数生成“设备 vN”。

## 3. 02B：手动黑白参考值

### P2-05：界面与语义

在“黑白场”区域增加原生参数卡片，与 ADC 设备设置分组展示：

```text
当前逻辑通道与 LED 映射

通道黑白参考值（RAW 16-bit ADU）
黑参考值   [          ]   [使用当前采样]
白参考值   [          ]   [使用当前采样]
来源：手动输入 / 当前采样 #... / 未设置
状态：本次编辑尚未应用 / 通道草稿已更新 / ...

[应用到通道草稿]  [撤销本次编辑]
明确清除已有参考值的入口

设备 ADC 参数（现有 offset / gain 等）
原有参数输入、读取和应用流程保持
```

字段名可以与现有资源命名一致。两个“使用当前采样”按钮分别填入黑／白编辑字段，不触发采样、不写硬件、不自动保存。已存在的“将列采样保存为黑／白参考值”旧入口如保留，语义仍保持且不与新填入动作同名混淆。

默认由一个“应用到通道草稿”动作原子提交这一对参考值。顶端原有“保存配置”负责文件保存。不得为新增手动输入另建持久化通道或自动落盘。

### P2-06：输入规则

输入应使用真实原始整数，不支持归一化百分比或显示 Gamma 后的值。

- 黑参考值：整数，`0 ≤ BlackLevel ≤ 65535`，允许未设置。
- 白参考值：整数，`1 ≤ WhiteLevel ≤ 65535`，允许未设置；不能静默把 0 解释为 null。
- 两者都有值时必须 `BlackLevel < WhiteLevel`。
- 清空编辑字段只是尚未提交的本地状态；只有明确应用／清除确认才修改通道草稿。不得在每次按键时把暂时空输入写回 null。
- 负数、小数、溢出、NaN、Infinity、无效文本均报本地化错误，不做静默 clamp、交换黑白值或自动调整另一字段。
- 复用现有数值解析约定；中文／英文切换不能改变保存的数值。`TextBox` 可保留；采用 `NumberBox` 时同样处理空值／中间输入态。
- 既有模型有更严格限制时服从模型并更新输入提示；不为通过输入修改模型语义。发现相互冲突时报告，而不是解除校验。

举例：黑 100、白 200 有效；黑 200、白 100 无效；白 0 无效；黑 0、白 65535 有效。黑 65535、白未设置只有在当前模型允许单独黑值时可保存，随后不能输入任何不大于它的白值。

### P2-07：数据写入必须为字段级 patch

先定位当前工作区内目标通道档案；手动编辑只修改 `BlackLevel`／`WhiteLevel`，保留该通道的参数快照、ROI、其他属性及其他通道。

优先使用 workspace 现有 mutation／更新方法。不能盲目调用一个会重新读取当前参数输入、`_roiSettings` 或写整个档案库的现成方法；需要在复用前确认它的真实副作用。必要时增加最小的字段级更新入口和测试，而非复制整个档案服务。

**默认目标是当前工作区草稿。** 只有用户随后执行原有文件保存／本地库保存动作，才持久化到对应位置。不得把“应用到通道草稿”实现成偷偷更新本地通道库。若现有服务把两者耦合，使用已有 workspace 编辑路径隔离；做不到时将此局部标记为阻塞，不能改变按钮承诺。

没有可编辑的目标通道档案时禁用应用并提示先完成通道配置；不要造默认曝光、默认 ADC 或虚假 ROI 来拼出一份“有效档案”。仅缺设备连接、但已有合法离线通道草稿时，应允许离线编辑；不能为档案编辑增加无必要的 `IsConnected` 条件。

更新后刷新草稿 dirty 状态、通道概览和必要的显示状态；不能直接把该通道标记成“已校准合格”“设备已验证”。来自复制或未验证的原始状态不得因手动填数被升级成实测认证。

### P2-08：撤销、采样来源和状态标签

撤销本次编辑恢复当前目标通道最新可用的草稿值，不恢复整个配置、不回滚设备。应用成功后，本次编辑基线可更新，文件 dirty 仍由 workspace 决定。

新编辑字段的采样来源至少包含采集标识、逻辑通道、使用的列范围和处理阶段；与当前通道不匹配、采样失效或来源无法确认时禁用“使用当前采样”，给出原因。

从当前有效 ROI／列采样值填入时沿用当前原始采样含义和取整规则。不要从 BGRA、直方图显示条高度或 Gamma 后的值填入。[S4]

“手动输入／采样填入”来源可以先作为本次会话 UI 元数据，不为它强制升级 schema。重新加载不含来源的旧文件时显示“来源未记录”，不能默认“采样测得”。

## 4. 并发、失败与上下文变化

### P2-09：捕获操作目标与有效性

提交时捕获目标工作区身份／代际、通道、预期版本和一对已验证数值。复用现有 mutation gate、runtime claim 或等价机制；新增档案编辑动作应进入适当的互斥分类，不能绕开正在进行的校准／通道写入。

目标工作区或通道在提交前已改变：拒绝过期提交。提交成功但返回时用户已看另一个通道：不得把旧结果覆盖到新通道的编辑框。异步操作取消不代表已提交的持久化可以随意回滚。

同一份档案上的自动校准候选审查与手动参考值提交不能发生静默竞态。默认在同目标候选处理期间禁用手动提交，并显示原因；不丢弃候选、不恢复已过期数值。跨通道并发按当前仲裁规则，不擅自放宽。

如果简化实现需要提交期间暂时禁止切换目标，可以在当前编辑区域实施；仍要通过代际检查抵御外部 workspace 更新、导航和断连回调，不能仅依赖按钮禁用。

### P2-10：失败语义

输入校验失败：保留输入及错误，不修改草稿、文件或设备。

workspace patch 失败／目标版本冲突：不得部分写入黑或白，不显示成功；允许用户查看当前值后重新提交。

文件保存失败：保留合法草稿和未保存状态，说明文件未更新。文件选择器取消不是保存失败，更不是保存成功。

设备应用失败：保留用户草稿；设备状态按现有结果标记未确认／需读回，不把草稿当成设备值。不能新增隐式重试或重新上电／移动设备。

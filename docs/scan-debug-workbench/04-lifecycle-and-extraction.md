# 阶段 04：生命周期评估与条件性职责拆分

> 先读 [README.md](README.md)。本阶段**可选，默认不执行**。
> 状态：待评估。第一次授权仅执行 04A；04B 需要独立明确授权。
> 目的不是减少文件行数，而是在证据充分时降低维护复杂度。

## 1. 为什么设置独立门槛

已核对的架构文档仍把 Page／ViewModel 提取与生命周期阻塞链关联，记录 `VM-001`、`UI-006`、`UI-007`、`VM-002` 等状态。[S3]

这些登记可能随工作基线变化，因此先复查当前源码与证据。不可凭历史测试通过、方法名包含 Cleanup、截图能打开或页面变好看，就宣布阻塞解除。

阶段 01～03 在不转移原有生命周期所有权的条件下可独立交付。阶段 04 被阻塞不应成为撤回已完成新布局或强行重写会话架构的理由。

## 2. 04A：只建立证据，不拆分生产所有权

### P4-01：当前调用与所有权图

读取当前 NavigationService／Page host、缓存策略、ScanDebugPage Loaded／Unloaded、ViewModel Attach／Deactivate／Cleanup、应用退出路径及相关测试。

画出或以表格记录：

| 资源／状态 | 必须说明 |
| --- | --- |
| 设备会话／访问租约 | 谁创建、谁释放、谁能取消、断连如何传播 |
| 运行任务与 CTS | 扫描、校准、自动对焦、手动移动的 owner 和完成等待 |
| ViewModel 事件订阅 | Attach guard、订阅次数、何时解绑 |
| workspace／设置／session 订阅 | Page 离开、返回、关闭时如何处理 |
| CanvasBitmap 与预览缓冲 | UI 线程、绘制使用与释放时序 |
| ROI／pan／manual focus pointer capture | 松开、丢失捕获、卸载和重排时的结束动作 |
| 对话框及 completion | 取消／卸载／异常时是否能完成等待 |
| dispatcher 工作项 | 旧页面／旧会话的迟到项如何识别并丢弃 |
| 03 阶段计算／基线（若已实施） | 取消、所有权、释放与导航缓存的关系 |

对每个解除订阅／释放／取消方法，检查实际调用者，而不只看定义。区分“离开但 Page 缓存保留”“再次进入”“设备替换”“应用关闭”四种场景。

### P4-02：最小生命周期状态契约

基于已有实现描述状态，不创建与当前会话管理平行的状态机。至少说明：

- 重复 Loaded 不重复订阅；重复 Unloaded／Cleanup 不多次释放同一资源。
- 未完成的旧 Deactivate 不能把重新激活的新会话解绑。
- 取消旧任务后迟到的结果不能更新新任务／新通道。
- 对话框等待不会因页面卸载永远挂起。
- Canvas 绘制不会使用已释放的 bitmap；后台分析不会读取已归还的数组。
- 不在 UI 线程阻塞等待异步操作；不以 `.Wait()`／`.Result` 解决清理顺序。
- 应用关闭如当前链路缺失，要如实报告，不在此任务里静默宣称已处理。

只记录证据和可测试契约。发现跨应用级生命周期修复需求时独立列为后续任务；04A 不自动实施大范围修复。

### P4-03：评估结论

对每一拟提取职责分别写 `READY` 或 `BLOCKED`。列出缺失证据、相关测试、影响范围与最小解除步骤。文档报告只影响此任务的评估，不擅自将仓库已有 issue 标记 Closed。

例如纯格式化／统计计算可能可独立测试，但 Page 预览所有权仍阻塞；不能因为前者可迁移就认为后者也可提取。

## 3. 04B：只在授权与证据同时满足时实施

### P4-04：提取前门槛

本轮拟提取部分必须满足：

1. 当前 registry 中相关阻塞已由真实代码与证据解决，或有已审查的适用于此局部的明确例外；不是由本任务自行删除阻塞标签。
2. 原有行为已由聚焦测试固定，状态和资源 owner 明确。
3. 涉及 WinUI 视觉树／生命周期转移时，有当前 Windows 运行证据；仅源契约测试不足。
4. 差分可以小步审查，并有不会丢失现有功能的回退路径。
5. 用户本次明确指定 04B 及具体提取对象。

门槛不满足时，保留已有生产结构，交付 04A 报告和独立解除阻塞建议。不能停掉整个已完成改造，也不能绕过门槛换一个名字实施同类拆分。

### P4-05：建议的最小提取顺序

顺序是建议，不是要求全部实现：

1. 无 UI 资源和订阅的纯计算／格式化／统计代码，先有行为测试。
2. 仅消费数据和命令的参数或检查面板。
3. 运行栏的展示部分，不转移实际任务所有权。
4. 最后考虑预览交互、对话框、复杂 workspace projection；这些最依赖生命周期证据。

不以把一个类拆成多个 partial 文件宣称完成职责拆分；也不为满足架构美观创建一层只转发所有属性和命令的无价值 Presenter。

### P4-06：组件契约

子控件由明确输入属性／依赖属性接收数据和命令。动态绑定明确模式，检查新 `x:Bind` 查找根与编译期生成绑定。[S8]

子控件不调用 `App.GetService` 再解析第二个 ScanDebugViewModel，不订阅设备事件来维护自己的连接状态，不自行 Attach／Deactivate 主工作台，不直接写参数或启动电机。

提取过程保持已有 public command／event／binding 契约；确需改名则更新全部生产调用、localization／automation 与测试，报告兼容性变化。保留 typed Page／ViewModel host 与导航契约。

一个局部控件卸载不应取消整个工作台任务。新的控件若拥有绘图资源，只释放自己的资源；共享 bitmap／缓冲区必须保持单一明确 owner。

### P4-07：测试迁移不能弱化约束

可以把只检查旧代码位置的测试替换为行为／新位置契约测试，但必须说明原来保护什么、现在如何继续保护。不能通过删除 lifecycle、no-hardware-call、workspace 或公共绑定断言来完成提取。

不要把既有测试数字抄进报告；在当前 commit 实际执行。增加失败／取消／重入用例，而不是只验证构造函数能调用。

## 4. 验证矩阵

| ID | 场景 | 通过标准 |
| --- | --- | --- |
| P4-T01 | 连续多次进入／离开页面 | 无重复订阅、残留 dispatcher 更新和新的内存增长趋势 |
| P4-T02 | 离开后迅速返回 | 旧 Deactivate 不会解绑新激活实例／会话 |
| P4-T03 | 运行中取消／导航／换设备 | 操作归属准确；旧回调不写新上下文 |
| P4-T04 | 对话框打开时卸载／关闭 | completion 明确结束，无永久等待和重复显示 |
| P4-T05 | ROI／平移／按住对焦时重排或丢失捕获 | pointer 状态可结束；不产生非预期持续运动 |
| P4-T06 | 预览绘制与清理重叠 | 无使用已释放资源、重复释放或跨线程访问 |
| P4-T07 | 冻结／基线／后台统计（如适用） | 清理与恢复符合原有策略；无旧计算污染 |
| P4-T08 | 应用退出 | 确认真实关闭链路；未覆盖时不能宣布整体生命周期修复 |
| P4-T09 | 命令／host／workspace 回归 | 所有受影响行为和禁止 UI 硬件直连约束保留 |
| P4-T10 | 缺运行环境 | 准确标记环境阻塞；不把源码测试冒充 WinUI 运行验证 |

没有真实设备时，软件 fake 的取消和归属测试仍可执行；电机、灯和物理断连效果另列 NEEDS_DEVICE_VALIDATION。

## 5. 阶段产出

04A：调用／资源所有权表、逐项证据、READY／BLOCKED 结论和最小后续修复任务，不做未经授权的架构调整。

04B：仅交付本次批准的一个提取切片、相应测试和运行证据。说明行为为何等价、哪些 owner 不变及如何回退。不可顺便拆分其他 Page 或引入通用全局框架。

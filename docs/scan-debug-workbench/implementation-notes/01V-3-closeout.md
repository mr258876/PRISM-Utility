## 3. BW1：明确“首屏”交付内容，不再以完整长表单挤入首屏

### 3.1 默认首屏必须同时可见

在与本轮问题截图相同的页面实际尺寸、系统缩放、文字缩放和语言下，黑白场初次进入且未滚动时，以下内容须完整可见：

1. 当前逻辑通道与物理映射的简要身份。
2. 黑参考值、白参考值两个编辑框，以及它们的单位／输入含义。
3. 显式应用与撤销本次编辑的入口，保留现有业务语义。
4. 本任务的主要自动校准动作组。
5. 与当前任务／通道关联的 ROI 紧凑摘要及“编辑”入口。
6. 当前验证状态摘要及“查看问题”入口；存在输入错误或阻塞时不能无提示。

完整验证列表、详细帮助、档案管理、算法／设备高级参数不要求全部首屏展开。

### 3.2 建议的顺序

```text
通道 [当前通道]                     [物理映射]

黑参考值 [       ]   白参考值 [       ]
[应用到通道]         [撤销本次编辑]
必要时显示与输入相关的错误，不静默隐藏

自动校准
[现有动作，保持原有命令与执行条件]

ROI   [当前实际范围/角色摘要]          [编辑]
验证  [实际问题数/阻塞状态摘要]        [查看]

▸ 详细说明、档案与高级设置
```

这是内容排序建议，不是新按钮名称、命令、ROI 角色或坐标的硬编码要求。使用当前真实模型、本地化与既有操作。

### 3.3 减少重复，而不是缩小和裁剪

优先消除重复的通道标题、重复解释相同状态的多行文本、无必要的卡片嵌套与过大间距。两个短数值输入可以并列；长说明横跨整组，不挤在其中一个输入框的窄列里。

不得通过统一缩小字号、缩放根布局、裁剪元素、硬设高度遮住内容、把主要动作搬入浮层或放大截图窗口来通过。

本轮优先在现有滚动参数区内调整内容分组。仅在实测证明确有必要时，才增加一个简短的常驻摘要区；不要建立多个嵌套滚动区域，不要重复创建一套编辑器。

### 3.4 ROI 与验证摘要的真实性

- 摘要必须来自结构化模型／现有可靠投影，不解析本地化的长说明字符串提取数字。
- 切换通道或 ROI 后同步更新；未知、未设置、不适用分别保留准确状态。
- 展示当前任务需要的真实 ROI 角色。若需要黑场／白场两种范围，明确各自角色，不虚构单一通用 ROI。
- 有多个问题时允许显示数量和简短类别；完整原文仍在既有详情中可查看、复制或定位。
- 输入格式错误和阻塞当前主要动作的关键原因仍在动作附近可感知。不是把所有错误藏到“详情”。
- “查看问题”打开原有验证入口，并保留已有跳转到字段与聚焦行为。
- 没有问题时不要占据一张高大的常驻警告卡片；没有完成验证时也不得显示“验证通过”。

### 3.5 超出默认条件时允许自然滚动

首次默认状态的完整操作组是验收对象，不要求任意数量错误、任意长名称或任意文字放大状态都不滚动。

在大文字或密集错误状态下，允许垂直滚动以保留内容和原生可访问性；不得让主要动作永久不可达，不得遮挡停止入口。错误详情展开不必继续维持默认首屏的高度目标。

## 4. TXT1：按语义换行，不给所有 TextBlock 全局禁用换行

### 4.1 原子单元

将数值与其单位／符号作为不可拆的视觉单元，例如“0.05 mm”“7450 px”“500 steps”。空格可在显示字符串中使用不换行空格；复杂组合优先拆成结构化短字段，使用各自不换行的显示单元。

- 不改变文本框输入、数字解析、数据单位、模型值或导出格式。
- 不使用 Unicode 字符串替换手段清洗用户输入来达到视觉目的。
- 不把整段运动摘要设成 NoWrap 再依赖省略号隐藏末尾。
- 不凭空把 WrapWholeWords 当作数值和单位不会分行的保证。

### 4.2 运动摘要

语义示例：

```text
距离   [完整数值+单位]
速度   [完整数值+单位]
方向   [当前方向]
```

空间足够时可以同行，空间不足时在字段之间换行。方向、距离及其他实际影响操作的关键参数不能只剩工具提示或被省略；不得改动运动命令与计算方式。

仅调整报告指出的摘要和相邻说明布局，不借此授权完整运动页面重构。

### 4.3 ROI 摘要

可按范围和宽度分为两个完整字段，在字段之间自然换行。例如“范围：起点–终点”“宽度：数值 px”。示例不指定真实坐标，也不改变当前坐标是否含端点的定义。

不要让单位、右括号或小数的尾部单独占行。若不换行单元本身超过容器，采用上下标签布局、可展开完整详情或其他能保留实际值的布局，不允许仅靠裁剪。

## 5. QA1：任务记忆必须在未被测试钩子覆盖的条件下验证

“QA 页面重载时强制选中采样”不足以证明生产代码有任务记忆缺陷。

- 先核查现有产品契约：是否要求导航离开后返回时恢复当前任务；如要求，检查当前真实流程。
- 首选在正常 Release 离线环境执行这个纯 UI 场景；不发送设备命令。
- 或在现有 QA 路径中定向关闭“每次重载强制选任务”，仅由测试驱动在初始布置时选择任务。不要为此修改生产默认行为。
- 测试：进入黑白场，输入未应用草稿；导航离开并返回；按既有契约验证任务选择、草稿和错误状态。导航不能触发保存、应用或硬件操作。
- 若当前环境无法执行，标记未验证并说明验证入口；不得把强制选中产生的结果记为产品 PASS 或 FAIL。

### 6.3 收尾规则

本轮一次定界修改后运行检查。允许针对这组验收问题进行一次小修；仍未通过则明确指出：哪一个控件、什么状态和尺寸、为何失败、剩余改动是什么。不要自动扩大范围或重做整个页面。

两位独立视觉审查是定位问题的辅助证据，不是把所有未知覆盖都无限并入本轮的理由。要求审查将问题分为：本轮范围内明确缺陷、范围外建议、证据不足。

## 3. 固定设计决定：身份头、编辑主体、摘要底栏

### 3.1 黑白场正常编辑态

在**现有左侧参数区内部**建立三行布局，不扩大或挪动整个参数列：

```text
左栏 Grid
├─ Auto：通道身份头
├─ *   ：当前内容区（编辑 或 问题详情，同一时刻只有一种可见）
└─ Auto：紧凑 ROI / 验证摘要底栏
```

正常编辑态示意：

```text
通道 [红 ▾]                              LED3
──────────────────────────────────────────
黑值 (ADU)                白值 (ADU)
[          ]              [          ]
[应用到通道草稿]           [撤销编辑]

缺少通道档案                 [配置当前通道]  ← 仅实际缺失时
本地输入未应用                               ← 仅实际有本地编辑时

[              完整自动校准              ]
[黑场 / 偏移]             [白场 / 增益]

▸ 采样来源、清除与帮助
▸ 通道档案与高级参数
──────────────────────────────────────────
黑白场 ROI                              [编辑]
活动区       当前范围 · 宽度及单位
屏蔽区       当前范围 · 宽度及单位
验证         当前准确摘要             [查看问题]
```

以上值和文案用于说明位置，**不硬编码红通道、LED3、坐标、档案状态或问题数**。

### 3.2 布局约束

- 身份头只展示一次当前逻辑通道与物理映射，不再接一段重复的“逻辑通道：红；LED 映射：LED3”。完整语义可由标签和可访问名称表达。
- 主体使用受 `*` 行约束的滚动区域。黑/白短输入成对排列，过窄或文字放大时允许变为上下排列。
- ROI 与验证**摘要、入口**在正常目标尺寸下有独立空间，不再依赖上方说明句恰好占几行。
- 底栏不放完整问题列表、说明书、大型 InfoBar 或无限增长的内容。不得把“固定底栏”实现成逐层嵌套滚动。
- 使用自然 `Auto/*` 尺寸；不硬设足以遮住内容的高度。默认状态应完整呈现黑/白输入、应用/撤销和三个自动动作；帮助与高级内容可滚动。
- 本地状态增长、问题详情、大文字下允许主体滚动，但摘要入口不得被半截裁切。极小窗口确实容不下固定区域时，明确切换成单滚动布局，保证所有内容可达，不让主体变为负高或零高。
- 不通过缩小全局字号、Viewbox 缩放、负 Margin、裁剪文字、压小点击目标或挤占预览来达到要求。
- 各组以小标题、对齐和间距区分；主要左栏容器内不再对每段文本都加卡片。

### 3.3 自动校准是明确动作组，不依赖 WrapPanel 偶然折行

采用“完整自动校准一行 + 两个单项动作一行”的显式布局；窄到不足时按预定规则纵向排列。保留全部三个原命令及其独立 CanExecute、提示、运行与取消行为。

文案必须与当前命令真实效果一致。排布中的视觉优先级不授权合并算法，不意味着完整校准可以取消或替代单项调节。保留原生 WinUI 样式，不为截图强行启用或高亮离线按钮。

## 4. 验证详情：直接显示错误，不再跳到旧通道库深处

### 4.1 本轮采用左栏局部详情视图

**点击“查看问题”后，左栏中间 `*` 区显式切换为问题详情；顶部通道身份、底部 ROI/验证摘要和右侧预览保持原位。** 这不是新窗口，不是新的应用页面，也不是叠加 Flyout。

```text
通道 [红 ▾]                              LED3
──────────────────────────────────────────
问题详情                              [返回参数]

实际问题消息
相关字段/通道摘要                       [定位修改]  ← 可导航时

下一条实际问题……

（只有这一处纵向滚动，可继续阅读全部问题）
──────────────────────────────────────────
ROI 摘要保持不变
验证  1 项阻塞问题                       正在查看
```

这项明确替代“打开通道库 Expander，再滚动到验证卡片”的旧交互。选择局部详情是为了让有限空间优先呈现实际错误，而不是继续同时塞编辑器、重复计数和错误列表。

返回参数时恢复原编辑区、原输入和打开详情前的编辑滚动位置。不要重新创建整套编辑器或从档案重新加载一次，导致本地未应用输入丢失。查看/返回均不得执行应用、保存、连接或校准命令。

### 4.2 复用数据，减少容器

- 使用现有 `ChannelCalibrationCurrentFilmProfileValidationIssueDisplays`、问题模板和定位命令；名称变更时按当前代码对应。
- 保留每个问题的来源、严重性、文本与能否导航的事实；标题不能暗示这份投影覆盖了它未包含的全部配置问题。
- 编辑 ScrollViewer 与问题 ScrollViewer 可以是同一 Grid 中互斥显示的兄弟区域；**不能祖孙嵌套接力滚动**。同一可见内容区只有一个纵向滚动所有者。
- 问题列表使用主体剩余高度，不再继承旧 `MaxHeight=160` 的内嵌小窗口。复用 ItemsControl 与单一 ScrollViewer即可，不为本轮新建虚拟化框架。
- 第一屏是实际消息，不是大号“当前配置验证”标题、重复计数、第二个 InfoBar 和第三层卡片。
- 同一处仅保留一份紧凑问题摘要。顶部全局审查入口和其他配置页中有独立用途的验证功能必须继续可达，不一刀切删除所有验证展示。
- 可导航问题保留明确的可执行入口；被动问题保持可读，不为了测试把它伪装成可导航按钮。
- 0 条问题显示准确空态；“没有已报告问题”不自动等于“已完成验证且通过”。

### 4.3 定位、返回与上下文变化

- 点击某条可导航问题时，调用原问题定位流程。目标属于本编辑区则先退出详情态，再展开必要编辑组，定位实际字段。
- 目标在其他现有配置区时按原导航契约执行，不修改问题所指向的真实范围。
- “返回参数”回到进入前的编辑上下文，焦点返回可见入口；因“定位修改”离开详情则聚焦实际字段，不强行滚回进入前位置。
- 切换通道时，按现有未保存输入保护完成通道切换；详情回到该通道的编辑态，旧问题的等待/焦点请求失效。
- 切换任务、关闭详情、离开页面、新请求覆盖旧请求时，旧的布局/滚动/聚焦操作必须失效。
- 页面整体任务记忆继续遵守现有产品契约，不因为这个局部详情状态重新设计导航记忆。

### 4.4 可见性与焦点的完成条件

简化结构后优先删除本路径不再需要的“卡片顶部偏移”补丁。确实仍需定位时：

1. 捕获当前激活、任务、通道及请求身份；等待当前目标展开和实际布局就绪。
2. 检查实际消息条目已加载、宽高为正且有限、祖先可见，而不仅是对象存在或 `Visibility=Visible`。
3. 将条目带入唯一视口；普通长度的第一条消息与动作完整可见。超长消息至少先显示其首段，全文与动作可连续滚动到达。
4. 确认目标矩形没有被祖先裁切，再在请求仍有效且用户未主动转移焦点时聚焦一次。检查聚焦结果。
5. 临时事件订阅在成功、取消、卸载时清除。不要通过固定 Sleep、连续强制 UpdateLayout、无限重试或永久 LayoutUpdated 监听解决时序。

控件存在、具有 AutomationId、能被 UIA Invoke、短暂拥有焦点或只有标题可见，均不算“查看问题成功”。

## 5. 状态文案与缺档案修复入口

### 5.1 三种状态分别处理

| 状态 | 主界面呈现 | 保持的边界 |
| --- | --- | --- |
| 本地输入尚未应用 | 简短“本地输入未应用” | 不等于通道草稿已更新，不等于文件已保存。 |
| 缺少可编辑通道档案 | 简短原因 + “配置当前通道”入口 | 不自动创建、保存或补默认参数来解除禁用。 |
| 已有输入/配置验证问题 | 输入错误靠近字段；配置问题在摘要与详情中有来源 | 不把既有档案错误归因于尚未验证的本地输入。 |

详细帮助仍可访问，但不在每次输入时铺开一段完整操作说明。真正的范围错误、不能执行的原因和动作限制不能仅藏进 Tooltip。

状态显示优先使用现有语义字段/标志；必要时增加少量只读 UI 投影。不要比较、截取或解析两段本地化长字符串来决定哪些事实应隐藏。

### 5.2 “配置当前通道”只做准确导航

复用现有档案配置入口，定位到能为当前通道处理缺档案问题的位置，而不是仅跳到通用配置名文本框。保留当前通道身份、未应用输入和已有确认流程；不得静默丢弃输入。

若当前没有能完成该操作的现有流程，说明具体缺口，不伪造已创建档案或放开按钮。该入口不意味着点击后允许自动写设备、写文件或创建档案。

### 5.3 数值与语义不变

保留黑白值为空的含义、原解析与验证时机、显式应用、撤销、清除、从采样填入及保存范围。不得因视觉改造变成失焦提交或输入即生效。

截图中 `65536` 是未应用本地输入。测试可以重现该状态，但不能把未调用的验证描述为“已检测失败”，也不能把截图的 1 条配置问题称为它引发的新错误。

短标签可以调整，但可访问名称与帮助应说明完整作用，例如“应用到所选通道草稿”；不能缩成暗示直接写设备的“应用设备”。

## 6. 运动区：只重排当前轴动作组，不改控制契约

采用以下固定顺序：

```text
当前电机 [实际电机/角色 ▾]                当前状态

移动方向 [原选择器]
移动值   [原输入]                       [原单位]
速度值   [原输入]                       [原单位]

本次动作摘要：实际距离、步数/时长、逻辑方向
必要限制：原始方向、物理方向未知等事实

[移动]                              [停止当前轴]

其他轴停止入口保持直接可达
▸ 低频电机配置与解释
```

要求：

- 将现有“移动”按钮放到相关参数和紧凑动作摘要之后，而不是方向旁、输入之前；不复制第二个含糊的执行入口。
- 在正常两栏默认状态，距离、速度、摘要中的关键值与执行/停止入口形成完整动作组，不把“移动”换到表单最底部的不可见位置。
- 保留当前轴停止、其他轴停止能力，以及顶部全电机停止。可复用现有各轴命令并调整布局，不新增一个语义不同的全局停止或运动路由服务。
- 电机身份在上方展示一次。修复 `Motor1：Motor1：` 的组合错误，查清名称/格式串来源，不靠任意字符串替换硬裁掉前缀。
- 摘要不重复电机身份；按完整字段分行。保留 `0.5 mm`、`0.1 s` 等数字/单位完整性，方向或关键值不靠省略号隐藏。
- 方向、角色、距离和速度单位来自当前模型；不凭截图擅自把 `steps` 改成 `steps/s`，不把指令估算值改称实测位置。
- `物理方向未知` 必须可见，不能为了简洁改成已知方向。逻辑 Z+ 不等于已经确认真实机械方向。
- 切换轴、打开说明、查看摘要只改变视图，不发运动命令、不重置用户输入。保持原 CanExecute、互斥、点动/停止和会话所有权。

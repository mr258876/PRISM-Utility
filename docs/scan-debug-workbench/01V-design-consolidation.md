## 0. 为什么需要本任务

用户在最新三张原生整窗截图中指出：任务菜单字号没有一致层级，顶部与底部反复提示连接状态，旧帮助文案未经筛选搬入新菜单，指引不明确，页面标题弱于局部设置标题。截图还暴露出对焦面板显示 BW 活动区、折叠菜单宽度不一、普通任务与工程控制混杂等问题。

此前任务着重防止裁切、保证预览面积、修复问题详情。部分要求已经实现，但这不能等同于全页设计完成。本任务的对象是**四个任务面板及公共区域的排版、内容、状态与导航的一致性**，不是第五轮只调整某个 Margin 的局部修补。

保留已有业务能力、输入保护、直接问题详情、设备命令与生命周期所有权；**不要求保留每一段旧说明、每一个旧容器或每一个旧入口的位置**。

本任务编写者已查看用户上传的三张整窗截图并核对部分当前代码，未运行 Windows、测试或实机。截图中的采样、运动画面包含已滚动的内容，不能据此宣称它们的首次进入位置错误。截图文件为用户提供的 `image(1).png`（采样）、`image.png`（对焦）、`image(2).png`（运动）；执行时优先使用实际附件或同一版本的原始图片，不假设这些文件已在仓库，也不以更早的 Root 截图替代这批整窗观察。

## 1. 本轮授权和边界

遵守适用的 AGENTS.md、用户未提交修改和仓库硬件安全约束。本任务替代旧 01V 文档中冲突的**视觉与执行范围限制**，包括“只许改黑白场”“不得调整公共标题”“所有原说明必须留在原菜单”“必须原封不动保留底部 StatusText 展示”等限制。更新 DESIGN.md 中被替代的页面规则；旧实施报告保留为历史记录，不修改旧证据。

授权：统一页面级样式；调整标题、配置操作、设备/任务状态、预览工具和底部辅助信息；重新筛选四个任务的说明与分组；将工程入口移到明确的工程区域；修复面板摘要的数据归属；补充必要的只读呈现状态和导航适配。

不授权：设备协议/算法/持久化格式变化；改变参数应用和文件导出的时机；自动建档或隐式写设备；取消或重命名成错误语义的停止命令；阶段4提取；全面拆分 Page/ViewModel；依赖升级、WebView2、通用 QA 平台或新的设备状态机。无需提交或推送，除非用户另行要求。

不要为了满足新的版式回滚黑白场输入保护、问题详情/返回/定位、ROI 摘要、按住点动释放、owner/epoch、对话框收尾或预览缓冲所有权修复。

## 2. 先建立一份内容清单，再实施

对公共区与四个任务逐个检查 XAML、Header/DataTemplate、隐式 Style、RESW 与最终计算样式。先在本轮唯一实施报告中生成以下清单；清单之后继续改代码，不以清单代替交付。

| 元素/资源键/绑定 | 所属任务与语义角色 | 当前样式和出现条件 | 用户依靠它做什么 | 处置 | 目标位置与验收 |
| --- | --- | --- | --- | --- | --- |
| 实际名称 | 标题/字段/状态/帮助/风险/动作 | 实际值 | 具体决策或动作 | 保留/改写/迁移/删除重复 | 可验证结果 |

所有常驻说明都必须有存在理由。保留是因为它影响当前动作、解释非显然参数或告知风险，不能只因为旧代码里有这个字符串。删除的是重复的呈现，不是底层错误信号、约束或业务能力。

所有用户入口也要有迁移记录，尤其是配置验证、待审查导入、照明测试、工程调试、设备设置和各轴停止。旧 x:Name/AutomationId 可以保留用于兼容，不等于视觉结构必须保留。

## 3. 统一的视觉层级

### DS-01：按语义统一，不是把所有文字设成一样大

以下为本项目建议的常规 100% 文本缩放基准。单位为 XAML 有效像素，不是截图物理像素。采用当前 WinUI 主题字体、字体回退与动态文字缩放，不固定最终文本高度。

| 语义角色 | 项目规范 | WinUI 对应/实现 |
| --- | --- | --- |
| 页面标题 | 28，Semibold；页面只一处 | 基于 `TitleTextBlockStyle` |
| 任务面板标题 | 16，Semibold；每面板至多一处 | 本项目角色样式，基于 BodyStrong 后集中设置 16 |
| 分组/Expander 标题 | 14，Semibold | `BodyStrongTextBlockStyle` 的页面别名 |
| 字段标签、输入、按钮、正文 | 14，常规；按钮保留原生样式 | `BodyTextBlockStyle`/原生控件资源 |
| 时间、来源、非关键辅助信息 | 12，常规/次级色 | `CaptionTextBlockStyle` |
| 阻塞原因、风险与输入错误 | 不小于正文角色；可换行 | 不降格成低对比度 Caption |

28/14/12 对应 Windows type ramp；16 面板标题是此工作台的项目选择，不声称它是微软固定规范。不要使用 20/28 号大标题装饰窄侧栏中的“高级”“保存状态”或工程说明。

至少提供清晰的页面资源名，例如 `ScanDebugPageTitleStyle`、`ScanDebugPanelTitleStyle`、`ScanDebugGroupTitleStyle`、`ScanDebugBodyStyle`、`ScanDebugMetadataStyle`。最终资源形式按现有工程实现；无需为抽样样式新增依赖。

### DS-02：统一所有四面板的折叠菜单

同一级 Expander 具有相同标题角色、内边距、左右对齐和箭头位置，默认占满参数轨可用宽度，不能按标题长短形成不同宽度的小盒子。按需使用 `HorizontalAlignment=Stretch` 和 `HorizontalContentAlignment=Stretch`；不要误以为只设置 ContentAlignment 就会统一 Header。

显式 Header TextBlock、HeaderTemplate、字符串 Header 与 RESW 属性都要检查。只改 Expander.FontSize 但留下 Header 内部的 Subtitle 样式不算完成。折叠/展开时宽度不跳变。

本页普通任务默认只使用一层详情披露；确需更深层的旧编辑器可留在配置/工程区域，不能把普通任务变成嵌套菜单目录。不要把功能入口都改成 Expander：瞬时命令使用 Button/菜单项；切视图用选中控件；仅同任务的次要设置才使用 Expander。

### DS-03：对齐、留白与表面

保持原生控件的焦点、禁用、悬停、高对比度和点击区域。间距使用小组内 4/8、组间 12/16、必要区域间 24 的少量资源，避免各处独立设值。不要全局缩字号、Viewbox 缩放、负 Margin 或固定文本高度裁切。

参数轨一个主表面，预览一个主表面；内部常用小标题、分隔与留白，不为每段说明再叠卡片。正常成功状态不用一张大型绿色 InfoBar 长驻。颜色不替代文本，不为了让离线图好看而高亮禁用动作。

字段标签位于输入上方。点动输入和 Z−/Z+ 应在同一个输入行对齐；标签单独占上行，距离限制横跨整组。不要把按钮垂直居中到“标签+输入”的总高度。

## 4. 公共区域：每个区域只负责一类事情

### IA-01：标题与配置身份分开

保留页面名称“胶片配置与校准”，首先修复层级，不借机更改整个产品命名。使用页面标题角色；“未命名胶片配置”和修改状态是较小的配置身份，不再像一句连续正文。

宽版尽量同排容纳页面标题、配置身份和文件动作。窄版有明确重排方案，不能为了大标题多叠一张高卡片。标题增强优先使用已有顶部空间，避免抵消已获得的预览高度。

核实“已保存”的实际含义：文件导出、通道档案保存和内存草稿基线不是同一件事。“未命名配置 · 已保存”不能未经核对就解释成已经写入 JSON。按照真实服务状态选择准确文案；不要通过改一个字符串虚构文件路径或导出事实。

### IA-02：配置入口不再是四个难区分的抽象按钮

建议的职责：

- `配置文件`菜单：新建、打开/导入、导出 JSON，以及原有文件相关操作；沿用各自命令和确认。
- `编辑配置`：进入现有配置编辑工作区，保留返回任务。
- `检查配置/配置问题`：真实检查命令与问题查看区分；静态无错误不能冒充“刚执行过检查”。
- 有待审查导入时显示明确的 `待审查导入` 入口/标记；普通态无需常驻“审查问题与导入”这个混合长标题。无待审查时相关导入功能仍在配置菜单可找到。
- `工程工具`：设备级参数、临时照明测试、采集调试开关等；与文件配置动作分组。

具体可以合并进有清楚分组的原生 MenuFlyout，而非增加同等权重按钮。不要把关键停止命令放进溢出菜单。配置问题全局计数与黑白场通道问题计数保留各自范围，不能为了去重合并不同作用域。

### ST-01：运行栏显示设备/当前任务，不拼接各按钮的禁用解释

当前 `RunStatusPanel` 同时呈现 `CaptureModeUnavailableReasonText`、`StartDisabledReasonText`、`StopDisabledReasonText`。改为一个有优先级的只读呈现：当前异常/动作失败、正在停止或执行的任务、阻塞开始的条件、就绪等。活动任务与连接异常必要时可以同时简明呈现，不用单一“未连接”覆盖一个尚待取消的本地任务。

“当前没有正在进行的采集”是停止按钮的禁用原因，不是应当与“请先连接设备”并列的主要状态。普通禁用原因保留在控件帮助/可访问说明；真正阻塞下一步的条件在运行栏或对应输入附近可见，不能只放 Tooltip。

复用现有结构化状态与 gate，不解析本地化长字符串决定严重性，也不另造设备状态机。可增加很小的只读 presentation model/属性，但不改变命令 CanExecute。

| 真实条件 | 显示重点 | 可用的下一步 |
| --- | --- | --- |
| 没有发现设备 | 未发现扫描仪 | 设备设置/检查连接；调用现有导航 |
| 已发现但未连接 | 扫描仪可连接 | 仅现有命令允许时显示连接动作 |
| 必需通道档案缺失 | 当前通道未配置 | 配置当前通道；不自动建档 |
| 必需输入无效 | 当前具体阻塞原因 | 定位对应输入；不只显示“不可用” |
| 可以开始 | 就绪 | 开始采集 |
| 执行/停止中 | 实际任务、阶段、进度 | 该任务已有的停止/取消入口 |
| 出错或断连 | 实际失败与下一步；保留未确认结果 | 现有重试/设置/详情路径 |

未知、未读取、未连接必须区分；不要把最后一次值当作当前设备确认值。不会因本次改样式自动执行连接或运动。

### ST-02：底栏不再次播报同一个连接提示

本轮明确允许调整底部 StatusText 的呈现职责，旧“始终显示最新 StatusText”不再是不可改变的设计限制。

优先将底栏用于当前图像/观测上下文：尺寸、通道、采集来源、光标原始值、冻结状态等，只呈现现有真实数据。无图像/无辅助信息时可为空或收起，不能生成示意数值填满。窗口级“未连接”仍由运行栏管理。VID/PID 等诊断标识移入设备详情，默认底栏不用完整句反复报告它们。

**迁移前盘点 StatusText 的所有生产路径。** 有些是连接提示，有些可能是操作失败或结果：错误必须仍在对应操作区或合适的通知入口可见；其他诊断可进入已有详情，没有历史存储则只能叫“当前诊断/最近消息”，不能凭空称为完整日志。禁止直接删掉 TextBlock 后让错误无处可见。

成功反馈可短暂出现或安静显示；未解决的关键错误不能因新的低优先级消息而消失。

### ST-03：空预览根据真实状态提供帮助

同一条“连接扫描仪后开始采集”不要在顶部、底栏和画布各出现一次。空态应告诉用户现在可以做什么，而不是复读设备状态：

- 离线时：可以先编辑配置，设备就绪后采样；连接入口在运行栏明确可见。
- 设备就绪但未采集：解释首次采样后会出现图像/线剖面，指向真实开始入口。
- 已有采集但未生成预览：说明是未生成/预览关闭/规模限制等实际原因，并提供已存在的导出或显示设置入口。
- 旧帧或冻结：不得仍写“无图像”，保留对应采集来源，不把草稿值当旧图像参数。

同一状态最多一个主要引导动作；不要求线性向导、不阻碍专家离线编辑、不为截图放假照片或模拟数据。

## 5. 说明文字：按用途决定保留，而不是统一折叠

### CP-01：强制完成以下内容整理

| 当前内容/可见现象 | 处理决定 | 原因/限制 |
| --- | --- | --- |
| “保存与验证状态”大卡片及重复“已保存” | 移除普通任务中的重复容器；配置状态归配置身份，问题归正确范围的检查入口 | 不删除验证逻辑，不把“有效”说成设备就绪 |
| “行数、距离、通道启用和顺序更改会立即更新摘要……” | 从常驻采样区删除或精炼成有必要时的帮助 | 是实现机制说明，不帮助当前选择；修改/导出范围须另有准确状态 |
| “通过扫描仪主板 USB 运动 API 暴露的三个电机的调试控制” | 移到工程帮助/开发文档 | 普通运动只需要轴、单位、状态与动作 |
| “用于工程验证的底层扫描流程开关……” | 工程调试区域内保留简短风险与默认要求，长解释折叠 | 危险/非常用行为不能隐藏风险，也不应挤占普通运动 |
| “仅当前会话的照明测试” | 工程工具中用“照明测试（本次会话）” | 保留会话作用域；日常采样所需通道/照明参数不可一并藏起来 |
| “本地输入未应用” | 保留短状态 | 与文件修改、档案问题不同，不改成已保存或已写设备 |
| “物理方向未知”、限位/距离限制 | 保留在动作附近，按实际状态显示 | 不能为了简洁删掉运动风险 |
| 正常点动说明再次复述输入值 | 仅有额外换算/限制信息时保留；正常重复值不再占一整段 | 实际限制、估算和单位仍应可查 |
| 大型成功 InfoBar“当前配置验证 有效” | 精简为对应配置的低干扰检查状态 | 无问题不等于校准合格、设备就绪或已做完整校验 |
| `预览配置` | 命名为“显示设置”并说明只影响显示（仅在实际作用符合时） | 与胶片/设备配置区分；不能改原始统计和输出语义 |
| `更多工具` | 根据真实菜单内容改为具体分组，如图像导出/叠加；混合菜单内标清分组 | 不为了短标题把 ROI 定位等功能藏得更深 |
| `Dir0/Dir1` 与 Motor 编号 | 有真实映射则并列显示机械角色，无映射保持原始值并说明未知 | 不猜物理正负方向，不丢失工程编号 |

其他未列出的说明按同一清单审查。不能只处理表里这些，然后宣布全页内容已完成。

### CP-02：文案原则

动作名使用清楚的动词和对象；范围说明放在组标题或状态中，避免每个按钮都写完整说明书。帮助回答“为什么/怎么选”，状态回答“现在怎样”，错误回答“哪里错/怎样处理”；不要互相代替。

工程细节、字段路径和 VID/PID 在详情中保留。范围、单位、数据来源、可能触发运动的警告、破坏性动作确认和当前阻塞不能以“降低文本密度”为由删除。简短中文与英文分别校验，不能只剪短中文，或把所有含空格的文案设为 NoWrap。

## 6. 四任务的一致结构和内容归属

### IA-03：采样

常用区：当前采集方式相关行数/通道/预览开关/必需参数，当前可执行动作所需信息优先。传送相关参数只在相应采集方式下处于主要层级；其他方式隐藏或降级时不得清除用户输入。

输出设置、完整计划与传送策略可作为统一的次级分组。工程临时照明测试移至工程工具。普通采样不再放大段保存机制说明或独立“保存与验证状态”卡片。必要的输入错误仍紧邻字段。

### IA-04：黑白场

保留已实现的通道身份头、编辑/问题主体互斥、ROI/通道验证摘要和返回/定位输入保护。将其纳入统一字号、分组和文案规范，不重写为旧嵌套滚动。

手动参考值、设备 ADC 参数、自动校准候选接受与 JSON 导出是不同动作。任何短文案都不能将它们混成一个“保存”。缺少档案仍提供真实配置入口；仅导航，不自动建档、应用或保存。

### IA-05：对焦——先校验摘要归属

用户截图在“对焦”任务下显示“所选 ROI：BW 活动区”。当前 XAML 的对焦首屏也绑定了通用 `RoiStatusText`。这至少表明呈现容易混淆；**尚未证明算法使用了错误范围**。

核对三个概念：全局图像叠加层当前选区、对焦 ROI 编辑对象、自动对焦服务本次实际评价的范围。对焦面板摘要应呈现后两者的真实关系。如果显示的是全局预览选区，明确标注“预览选区”，不能充当“对焦范围”。未选择/未定义则按事实说明；不要切到对焦就偷偷修改 ROI、填入坐标或宣称算法已换范围。

结构采用一致的小标题：自动对焦、手动点动、对焦范围、搜索参数（次级）。正常/快速/精细入口可精简表述，但只有确认命令仅为同一操作的预设时才可合成一个预设选择；否则保留独立命令，不借视觉统一重写算法。

自动对焦状态只有一个明确位置。停止全部对焦保持既有安全语义；离线时某个停止仍可用不必然是 bug，可能用于取消本地工作，不为颜色一致强制禁用。

Z−/Z+ 与点动输入对齐。重复正常距离说明可减少；超限、换算和未知运动状态必须保留。

### IA-06：运动

保留已改好的方向/距离/速度/真实估算摘要/移动与停止顺序，不再返工。当前轴身份和必要状态在操作组顶部；其他轴停止仍可直接找到，全局停止常驻。

把工程照明、采集底层调试开关从普通运动内容移至工程工具；本任务不删除这些能力。轴的低频使能/配置可在明确的“轴设置”披露里，危险动作保持原警告与确认。

审查速度单位的显示量纲：若底层枚举复用了距离单位而实际含义为每秒，应在显示层标出真实速率单位；验证绑定再改文案，不能只把所有 `steps` 替换为 `steps/s`，也不改底层值。

### IA-07：滚动、返回与导航一致

首次进入任务应从常用区开始；同一任务离开再返回可保留自己的滚动位置。不得用一次全局滚动偏移套四个不同面板，也不因状态刷新/控件重排反复复位。必要时在深层配置提供回到当前任务/常用参数的清楚入口，复用现有导航状态，不另造路线。

用户这次采样与运动截图已经处在中下段；只能验证当前位置是否清楚、有无相关内容混杂，不能以这些静态图证明首次进入或返回逻辑错误。单独运行导航测试。

工程工具作为已有高级工作区的明确入口，不把普通任务选择器扩为一排互相重叠的新任务。普通区和工程区里同一个命令/输入不得创建第二份不一致的状态源。

## 7. 建议的整页结构

下图仅表达区域职责，不是必须逐像素复制的线框。优先复用已改善的原生布局。

```text
胶片配置与校准        当前配置 · 修改/导出状态      配置文件 ▾  编辑配置  工程工具

设备与任务状态 [必要的下一步]   采集模式 [实际模式 ▾]    开始采集  停止采集  停止全部电机

采样  黑白场  对焦  运动          图像  线剖面      缩放  显示设置  图像工具 ▾  信号检查
┌ 当前任务参数 ──────────┐      ┌ 图像/曲线观察区 ──────────────────────┐
│ 当前身份、常用操作      │      │ 真正的图像或状态相关空态               │
│ 次要设置/上下文帮助     │      │ 不用一个黑白场错误占据整个采样工作区   │
│ 问题正文按需切换        │      │                                       │
└ 摘要与必要入口 ────────┘      └ 真实图像上下文/光标/来源 ─────────────┘
```

没有图像时不要求填满底部；有图像时优先可读观察面积。检查侧栏保持已有能力，不强制所有窗口三栏。屏幕物理像素、内容区 DIP、文字缩放分别记录，不能从聊天缩放后的图片反推字体点数。

## 8. 代码实施位置与防回归要求

优先检查：`Views/ScanDebugPage.xaml`、对应 code-behind、`ViewModels/ScanDebugViewModel.cs` 的只读呈现与导航、`Strings/zh-CN/Resources.resw`、`Strings/en-us/Resources.resw`、现有页面资源/布局计算、`DESIGN.md`。必要时修改 Shell 的页面特定展示，但不全局改变其他页面。

当前值得重点审计的对象：

- `WorkbenchTitleTextBlock` 的 BodyStrong 用法，与局部分组的 Subtitle 样式。
- `RunStatusPanel` 的多禁用原因并列和底部通用状态消息。
- `RoiStatusText` 在对焦、黑白场、检查区中的不同语境。
- `Expander.Header` / `HeaderTemplate` 中继承或显式设置的字体。
- 各个旧 `*Description`、`*HelpText` 和 `*StatusTitle`，及其默认可见性。
- 菜单迁移后旧错误定位、延迟加载、键盘焦点、点击与按住运动释放路径。

样式变更不要破坏 x:Bind 根对象、生成绑定或 x:Uid 的本地化赋值。移动已有元素必须更新错误定位和 UIA 查找的目标，但测试不能反过来要求旧容器结构永远存在。

呈现层按真实类型化状态决定轻重缓急；不要通过比较已翻译的提示文字判定设备状态、丢失错误或决定能否写硬件。只读摘要变更不能反向触发参数写入。

### 9.2 运行过程

| ID | 场景 | 结果要求 |
| --- | --- | --- |
| F1 | 离线首次进入 | 设备状态清楚，可离线编辑，下一步入口真实；不重复三处相同指引，不声称文件已保存或设备就绪。 |
| F2 | 每个任务先滚动，再切走并返回 | 首次/返回策略一致；不出现跨任务串用滚动或状态变化自动跳转；有明确返回路径。 |
| F3 | 黑白输入未应用→看问题→定位/返回 | 原本已修好的流程无回归，输入不丢、不自动应用、不自动建档。 |
| F4 | 正常任务与工程工具切换 | 参数仍为同一源，旧命令能力完整；隐藏控制不发硬件指令。 |
| F5 | 对焦范围编辑/预览选区变更 | 摘要与来源对应，不意外改变另一个范围；若算法本身存在问题，另报并定界。 |
| F6 | 状态生产路径中的操作失败 | 即使底栏改职责，失败仍能在合适位置看到；普通连接消息不能覆盖它。 |
| F7 | 英文、浅色/深色与较大文字 | 同级层级保持，允许合理换行与滚动，关键字段/按钮不裁切；禁用及焦点仍原生可辨。 |

常规几何回归参考仍为 Root `977×604 DIP`、预览 `645×396 DIP`；宽版参考 Root `1305×809 DIP`、预览 `950×601 DIP`。在可比正常态不减小预览，通过删除重复区域、整理操作行吸收标题尺寸增加；不扩大窗口过关。较小窗口、文字放大、长错误态另外检查可达性，不硬套常规像素门槛，也不强设高度裁切达标。无法同时满足时报告具体取舍，不偷偷降低字体或改测试参考值。

首次不必连接实机就能验证样式、内容、导航与离线状态。在线/采集中/有 RAW 的运行证据随后从真实数据或现有隔离测试条件获取；使用测试条件须明确标记，不能当实机结论。不要以等待硬件为由跳过全部离线设计工作。

## 10. 交付与执行方式

执行顺序：先盘点角色与文案；落地共享字体/Expander/标题规范；分配状态与入口职责；同步完成四任务的内容整理；最后检查完整流程。可以内部小批提交给工作树，但不要每改一个按钮就另写一份“下一轮”任务书。

交付仅需一份实施报告，附内容处置清单、实际改动、必要的前后整窗截图与局部放大、任务流程结果、测试/构建和未验证项。每个任务至少一张普通编辑态；另拍问题详情、工程工具、一次必要的状态引导。已滚动状态与默认状态明确区分。

截图能证明字形/对齐/呈现，行为测试能证明输入与命令，二者不能互相替代。源码字符串断言不能单独证明视觉一致或错误仍可见。测试数量不作为设计评分。

执行范围内有可复现失败时修复再验，不以旧“两轮后停止”为由中止，也不无限增加新要求。环境或预算不足则准确区分 PASS、FAIL、NOT_RUN，并指出具体剩余项。不要为本任务扩建通用捕获工具、更新无关依赖或开展阶段4。

完成后不自动提交/推送，不自动启动新阶段。
